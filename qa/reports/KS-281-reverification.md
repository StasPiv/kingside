# KS-281: Повторная верификация drag-and-drop (KS-278)

**Дата:** 2026-03-09
**Статус:** FAILED — E2E тесты не валидны, требуется ручная проверка

## Результаты E2E тестов

- **11 из 17 тестов FAILED**
- **6 "passed" — ложноположительные** (проверяли отсутствие артефактов, что тривиально истинно когда drag не стартует)

## Критическая находка: Drag-and-drop НЕ работает в Playwright

Скриншоты (сохранены в `apps/e2e/test-results/ks281-s*.png`) показывают:
- Все скриншоты **идентичны** — до drag, во время mousedown, во время перемещения, после drop
- Ghost-элемент **никогда не создаётся**
- Фигура **не становится невидимой** (opacity не меняется)

### Вероятная причина

Из error-context (Playwright accessibility snapshot): все кнопки-клетки доски имеют атрибут `[disabled]`
(react-chessboard рендерит `button[disabled][data-square]` когда `allowDragging: false`).
`useFastDrag` слушает `pointerdown` на контейнере, но в headless Chromium pointer events
могут не пробрасываться через disabled buttons корректно.

## Анализ кода useFastDrag.ts — проблема "smooth release"

Обратная связь @StasPiv: "фигура не отпускается плавно".

Код `onPointerUp` (строка 138-159):
```typescript
state.pieceEl.style.opacity = '';  // мгновенное восстановление видимости
state.ghost.remove();              // мгновенное удаление ghost-элемента
```

**НЕТ CSS-перехода или анимации** при drop. Ghost мгновенно удаляется, фигура мгновенно появляется
на целевой клетке. Визуально это выглядит как "телепортация" — фигура резко исчезает из позиции
курсора и появляется на клетке без плавного перехода.

## Выводы

1. E2E тесты drag-and-drop невалидны — drag не стартует в Playwright
2. Предыдущая E2E верификация была ложноположительной
3. В коде отсутствует анимация/transition при drop — это может объяснять жалобу на "неплавное отпускание"
4. Требуется: ручная проверка в реальном браузере + исправление анимации drop от @frontend
