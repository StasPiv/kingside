# Git Workflow

## Ветки

- Каждая задача — отдельная ветка: `feature/KS-XX`
- Ветка создаётся от `main`
- После завершения работы — pull request в `main`

## Коммиты

- Формат сообщения: `KS-XX: краткое описание`
- Максимум 72 символа
- Без коммита задача не считается выполненной

## Pull Requests

- Изменения сливаются в `main` только через pull request
- PR должен содержать номер задачи в заголовке

## Правила для всех агентов

1. Перед началом работы — создать ветку `feature/KS-XX`
2. Коммитить изменения с указанием номера задачи
3. По завершении — открыть pull request
4. Без коммита и PR задача не может быть переведена в Done

## Координация агентов (ADR-006)

### Запрет параллельных экземпляров

- **ЗАПРЕЩЕНО** запускать второго агента той же роли на задачу, которая уже "В работе"
- **ЗАПРЕЩЕНО** запускать QA параллельно с разработкой — только после "In Review"
- Статус задачи в Jira — единственный источник правды о том, кто сейчас работает

### Последовательность работы над задачей

```
1. Координатор назначает задачу → агент переводит в "В работе"
2. Агент работает → коммитит → переводит в "In Review"
3. QA проверяет → комментирует результат
4. Если баг — задача возвращается в "К выполнению" для ТОГО ЖЕ агента
5. Если ок — задача переводится в "Done"
```

### Фиксация работы в Jira

Каждый агент обязан:
- При старте: перевести задачу в "В работе" + комментарий `ROLE: начал работу`
- При завершении: комментарий `ROLE: работа завершена` + перевод в "In Review"/"Done"

### Параллельная работа разных ролей

Параллельный запуск backend и frontend на одну фичу допускается ТОЛЬКО если:
- Они работают в разных файлах/модулях
- Это явно указано координатором в описании задачи
- Каждый работает в своей ветке
