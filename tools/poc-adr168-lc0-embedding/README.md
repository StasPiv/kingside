# PoC ADR-168 — вектор позиции из скрытого слоя Lc0 (KS-4989)

Проверка гипотезы ADR-168: пригоден ли скрытый слой сети Lc0 как пространство
похожести позиций (расстояния отражают **характер/исход**, а не число сделанных ходов).

## Что реализовано
- `lc0poc.py` — парсинг весов Lc0 (`.pb.gz`, dequant uint16, fold BN по
  `network_legacy.cc`), кодирование `FEN→112 плоскостей`
  (`INPUT_CLASSICAL_112_PLANE`, `HistoryFill=fen_only`), прямой проход ствола
  (SE-ResNet) в numpy по `network_blas.cc`/`se_unit.cc`. Извлечение вектора со
  скрытого слоя, пулинг `flat` (C·64) или `gap` (среднее по 64 клеткам, C).
  **Нормализация перспективы «к ходу»** (главная ловушка §5): при ходе чёрных
  доска зеркалится (`board.mirror()`), сравнение — в единой системе; плоскость
  «чей ход» сохраняется как в оригинале Lc0. Метрика — косинус.
- `data.py` — выборка позиций из мастер-партий (Carlsen.pgn, 405 партий),
  детерминированная структурная метка (6 классов пешечной структуры).
- `run_all.py` — валидация прямого прохода + 3 теста ADR §4 с базовыми линиями.

## Сети
- `744706.pb.gz` — **самоигровая** сеть Lc0 (SE-ResNet 10×128, WDL) —
  соответствует обоснованию ADR (обучение на исход/лучший ход). **Основная.**
- `maia-1500.pb.gz` — Lc0-архитектура, но обучена имитировать ход человека 1500.
  Используется как эталон для **валидации прямого прохода** (у неё корректно
  декодируется голова value → сверка со Stockfish).

Скрытый слой транформерных сетей (BT/T-серии) в numpy не считается; реализация
их attention-body — вне объёма PoC.

## Валидация прямого прохода (обязательна до тестов)
- **Перспектива:** вектор позиции white-to-move и её цвето-зеркального двойника
  black-to-move различаются **только** плоскостью «чей ход» (rel. 3–5%), т.е.
  ориентация доски нормализована верно. Ловушка §5 закрыта.
- **Голова value vs Stockfish** (Maia, несбалансированные позиции): corr 0.69,
  оценки осмысленны (ферзь вперёд → +0.85). Прямой проход корректен.
- **Ствол 744706** проверен независимо от его головы value: линейная проба
  «знак материала» из ствола = 0.79 ≈ Maia 0.82 (эталон корректного ствола).
  Ствол 744706 валиден; расхождение головы value 744706 — отдельный дефект
  декода головы, на тесты не влияет (тесты используют только ствол).

## Результаты (сеть 744706, самоигровая; слои 5/7/10 из 10; n=250 для теста 2)

Пороги зафиксированы ДО прогона: T1 — доля соседей выше случайной базы с запасом;
T2 (критичный) — медиана расстояния после зевка заметно больше, чем после тихого
хода (порог: отношение >1.3 и доля(зевок>тихий)>0.6 на средне-позднем слое);
T3 — линейная проба читает свойство выше случайного.

**Тест 1 «Соседи»** (top-10, исключены соседи из той же партии), база 0.209:
| слой·пулинг | доля одной метки | lift |
|---|---|---|
| b5-flat | 0.357 | **×1.71** |
| b7-flat | 0.333 | ×1.59 |
| b10-flat | 0.310 | ×1.48 |
| b5-gap | 0.303 | ×1.45 |

→ **ПРОЙДЕН** с запасом.

**Тест 2 «Характер, а не ходы» (КРИТИЧНЫЙ)**, косинус-расстояние от позиции:
| слой·пулинг | тихий (лучший) | зевок ≥300cp | случайный | зевок/тихий | доля(зевок>тихий) |
|---|---|---|---|---|---|
| b5-flat | 0.303 | 0.309 | 0.301 | ×1.02 | 0.612 |
| b7-flat | 0.340 | 0.350 | 0.341 | ×1.03 | 0.676 |
| b10-flat | 0.380 | 0.399 | 0.381 | ×1.05 | 0.600 |
| b7-gap | 0.043 | 0.056 | 0.044 | **×1.32** | 0.664 |
| b10-gap | 0.094 | 0.128 | 0.109 | **×1.36** | 0.624 |

→ **ПРОЙДЕН предельно, только с пулингом `gap` на средне-позднем слое** (×1.32–1.36).
С пространственным пулингом `flat` расстояние определяется фактом перемещения
фигуры, а не сменой характера (×1.0) — это ровно ловушка «число ходов» из §2.
Порядок тихий < случайный < зевок соблюдён (gap).

**Тест 3 «Проба смысла»** (линейная проба из вектора):
- «есть проходная» (вычислимо), база 0.689: **b5-flat 0.823** → ПРОЙДЕН с запасом.
- «кто лучше» (знак оценки SF, |e|>50cp), база 0.622: **b10-flat 0.689** (+0.067) →
  выше случайного слабо.

## Вердикт
Пространство похожести **условно пригодно, но со слабым критичным сигналом.**
- T1 и T3(проходная) — уверенно да.
- T2 (критичный) — сигнал присутствует и направлен верно (зевок дальше тихого),
  но модест (×1.3) и виден лишь при `gap`-пулинге на средне-позднем слое; при
  `flat` теряется в «геометрии хода».
- T3(кто лучше) — едва выше случайного.

По §4 это **пограничное подтверждение**, не чистый зелёный свет: скрытый слой
классической самоигровой Lc0 несёт «характер», но выделяется он слабо и требует
правильного представления (`gap`, средне-поздний слой). Перед раскрытием φ*/планов
(§6) — решение координатора/architect: (а) принять модест-сигнал с gap-пулингом,
либо (б) перепроверить на сильной трансформерной сети (BT/T) с валидированным
прямым проходом (сборка lc0 → ONNX → onnxruntime), чтобы понять, усиливается ли
критичный сигнал.

## Воспроизведение
```
# окружение (numpy, onnxruntime — системные; доустановить в /tmp/ks4989-libs):
python3 -m pip install --target=/tmp/ks4989-libs onnx scikit-learn grpcio-tools meson ninja
# proto: скомпилировать libs/lczero-common/proto/net.proto -> /tmp/ks4989-proto/net_pb2.py
# сети:
curl -L https://storage.lczero.org/files/networks-contrib/744706.pb.gz -o /tmp/744706.pb.gz
curl -L https://github.com/CSSLab/maia-chess/raw/master/maia_weights/maia-1500.pb.gz -o /tmp/maia-1500.pb.gz
# мастер-партии: pgnmentor Carlsen.zip -> /tmp/ks4989/Carlsen.zip
python3 data.py                 # -> fens.txt (4000 позиций)
NET=/tmp/744706.pb.gz python3 run_all.py "5,7,10" 250
NET=/tmp/maia-1500.pb.gz python3 run_all.py "2,4,6" 250   # эталон-валидация
```
Требуется Stockfish (`/usr/games/stockfish`) для тестов 2/3b.

# KS-4990 — те же тесты на сильной трансформерной сети Lc0 (BT/T)

Продолжение KS-4989: проверка, усиливается ли критичный тест 2 на современной
трансформерной сети (attention-body), или слабость — в самом подходе.

## Сеть и путь
- `t1-256x10-distilled` — самоигровая трансформерная сеть Lc0 (attention body,
  10 слоёв encoder, d_model 256, attention-policy, WDL).
- Скрытый слой руками не считается. Путь: собран `lc0` (`meson -Dbuild_backends=false`,
  `scripts/compile_proto.py` вместо protoc) → `lc0 leela2onnx` → ONNX →
  `onnxruntime` (CPU). Промежуточные тензоры `/encoder{5,7,9}/ln2` добавлены в
  выходы графа (`onnx.helper`), сняты активации (64 токена-клетки × 256).
- `lc0onnx.py` — сессия onnxruntime + переиспользование валидированного
  кодировщика FEN→112 плоскостей из `lc0poc.py`; `run_onnx.py` — те же 3 теста,
  те же 4000 позиций и пороги, что в KS-4989.

## Валидация прохода (обязательна)
- Перспектива «к ходу»: вектор white-to-move и цвето-зеркального двойника
  различаются на 0.5% (усреднение) — ориентация нормализована.
- Голова value vs Stockfish (несбалансированные позиции): **corr 0.92**
  (у ResNet-эталона Maia было 0.69). Проход через ONNX корректен.

## Результаты (t1-256x10; слои encoder 5/7/9 из 10; n=250 для теста 2)
Сигнал сосредоточен в **самом глубоком слое encoder9** (абстрактный характер/исход).

| Тест | лучший слой·пулинг | трансформер t1 | ResNet 744706 (KS-4989) |
|---|---|---|---|
| T1 «Соседи» (lift) | encoder7-flat | ×1.72 | ×1.71 |
| T3a «проходная» | encoder9-flat | 0.82 / база .69 | 0.82 / .69 |
| **T2 критичный (зевок/тихий)** | **encoder9-gap** | **×4.25**, доля(зевок>тихий) **0.968** | ×1.36, 0.62 |
| T2 (encoder7-gap) | | ×2.63, 0.880 | — |
| **T3b «кто лучше»** | **encoder9** | **0.925** / база .55 | 0.689 / .62 |

Пулинг: `gap` (усреднение по клеткам) на глубоком слое даёт максимальный разрыв
характера; `flat` слабее (×1.48 на encoder9) — как и на ResNet, пространственное
представление частично тонет в «геометрии хода».

## Вердикт KS-4990
Гипотеза ADR-168 на сильной трансформерной сети **уверенно подтверждается.**
Критичный тест 2 вырос с ×1.36 (ResNet, пограничный) до **×4.25** (зевок почти
всегда дальше тихого хода, 96.8%); «кто лучше» читается линейно с точностью
**0.925** против 0.69. Пограничность KS-4989 была ограничением силы/архитектуры
сети, а не подхода: пространство похожести из глубокого слоя attention-body Lc0
пригодно и отражает характер/исход, а не число ходов.

Рекомендация: для §6-надстройки (φ*, планы) брать глубокий слой (последний
encoder) трансформерной сети + усреднение по клеткам; извлечение — через
leela2onnx→onnxruntime (воспроизводимо, без ручного прохода).

## Воспроизведение (KS-4990)
```
# сборка lc0 (нужен meson+ninja из /tmp/ks4989-libs):
cd /tmp/lc0 && PATH=/tmp/ks4989-libs/bin:$PATH meson setup build -Dgtest=false -Dbuild_backends=false && ninja -C build lc0
# сеть + конвертация:
curl -L https://storage.lczero.org/files/networks-contrib/t1-256x10-distilled-swa-2432500.pb.gz -o /tmp/t1-256x10.pb.gz
/tmp/lc0/build/lc0 leela2onnx --input=/tmp/t1-256x10.pb.gz --output=/tmp/t1-256x10.onnx
python3 lc0onnx.py                      # валидация прохода (перспектива + value vs SF)
python3 run_onnx.py /tmp/t1-256x10.onnx 250
```

# KS-4994 — пакетный конвейер эмбеддинга корпуса → position_embedding (ADR-169)

Наполнение таблицы `position_embedding` (archive-db, KS-4993) векторами позиций
из корпуса сильных партий. Питает «проверку глазами» (ADR-169 §1).

## Конфигурация (ADR-168 §9 / ADR-169 §2.3, §2.5)
- Сеть: `t1-256x10` (трансформер), слой `/encoder9/ln2`, усреднение по клеткам
  → `vector(256)`. Извлечение: `leela2onnx → ONNX → onnxruntime`, CPU.
- **Инвариант перспективы/истории (§2.5):** вектор считается через тот же
  `lc0poc.encode` (перспектива «к ходу» + `HistoryFill=fen_only`), что и запрос.
  `query_similar.py` использует ту же функцию — расстояния сопоставимы.
- `position_key` = sha256(поля FEN 1–4: расстановка, очередь, рокировки, e.p.) —
  идентичность позиции без счётчиков; устранение дубликатов по корпусу.

## Корпус
- `build_index.py` читает все `*.zip` из каталога корпуса (pgnmentor, топ-игроки:
  Carlsen, Kasparov, Karpov, Anand, Kramnik, Fischer, Caruana, Nakamura,
  Nepomniachtchi). НЕ прод-архив (ADR-169 §2.1). Выборка: ходы 14–100, шаг 8 плаев
  по партии, устранение дубликатов по `position_key`.
- Наполнено на dev (`kingside_archive`): **120 000** уникальных позиций,
  `source='master'`. Время: ~19 мин, один процесс (≈130 поз/с, совпадает с §3).

## Проверка «глазами» (топ-5 по косинусу через HNSW)
`query_similar.py` (кодирует запрос идентично индексу). Примеры:
- Пешечный эндшпиль → все 5 соседей — чистые пешечные/королевские окончания (d 0.07–0.12).
- IQP/закрытый центр d4-c4/d5-c5 → родственные дебютные структуры (d 0.014–0.019).
- Итальянка (открытый e4/e5, развитые фигуры) → открытые дебюты того же типа (d 0.02–0.023).
- Ладейное окончание → упрощённые окончания с ладьями/лёгкими (d 0.02–0.027).
Кластеры структурно осмысленны; перспектива «к ходу» корректна (соседи с обеими очередями хода).

## Запуск
```
python3 -m pip install --target=/tmp/ks4989-libs pg8000   # драйвер записи в Postgres
mkdir -p /tmp/ks4989/corpus                                # положить *.zip PGN (pgnmentor)
ARCHIVE_DATABASE_URL=postgresql://kingside:kingside@localhost:5432/kingside_archive \
  python3 build_index.py /tmp/ks4989/corpus /tmp/t1-256x10.onnx 120000
ARCHIVE_DATABASE_URL=... python3 query_similar.py            # проверка топ-5
```
Границы: наполнение только на dev. Маршрут `/positions/similar` и кодировщик
запроса как сервис — отдельной задачей (ADR-169 §2.3/§2.4).

# KS-4995 — тестовый маршрут /positions/similar + сервис-кодировщик (ADR-169 §2.3/§2.4)

Внутренняя «проверка глазами»: по FEN → топ-5 ближайших позиций из
`position_embedding`. Без публичного UI.

## Архитектура (ADR §2.3: onnxruntime НЕ в основном API)
Два лёгких процесса в зоне PoC (основной NestJS API не трогается):
- `encoder_service.py` (:8181) — `GET /encode?fen=…` → `{dim, vector}`.
  Держит onnxruntime + сеть t1-256x10, слой `/encoder9/ln2`, усреднение по
  клеткам. Кодирует через общий `lc0poc.encode` — тот же путь, что построение
  индекса (**инвариант §2.5**: перспектива «к ходу» + `HistoryFill=fen_only`).
- `similar_service.py` (:8182) — `GET /positions/similar?fen=…&k=5`. Тонкий:
  берёт вектор запроса у кодировщика по HTTP, ищет топ-k по косинусу (`<=>`,
  HNSW, `SET hnsw.ef_search=100`) в `position_embedding`, возвращает JSON
  `{fen, game_ref, ply, side_to_move, cos_dist}`.

Продуктивизация (реальный маршрут рядом с `by-position` + сайдкар-кодировщик) —
отдельным решением при переходе от «глаз» к функции (ADR §2.3, вне scope).

## Запуск
```
PYTHONPATH=/tmp/ks4989-libs:/tmp/ks4989-proto python3 encoder_service.py 8181 &
ARCHIVE_DATABASE_URL=postgresql://kingside:kingside@localhost:5432/kingside_archive \
  PYTHONPATH=/tmp/ks4989-libs python3 similar_service.py 8182 &
curl 'http://127.0.0.1:8182/positions/similar?fen=<URL-encoded FEN>&k=5'
```

## Примеры (совпадают с прямой проверкой query_similar.py → §2.5 соблюдён)
Запрос `8/5pk1/6p1/7p/7P/6P1/5PK1/8 w - - 0 40` (пешечный эндшпиль) → соседи:
d=0.068 `8/6p1/5k1p/8/5K2/7P/6P1/8` (Ding–Carlsen), d=0.091 … — все пешечные/
королевские окончания.
Запрос `r1bq1rk1/pp2bppp/2n1pn2/2pp4/2PP4/1PN1PN2/P2B1PPP/R2QKB1R w KQ - 0 8`
(закрытый центр d4-c4/d5-c5) → d=0.014 … родственные закрытые дебютные структуры.
Соседи с обеими очередями хода — перспектива нормализована.
