# Критерии модерации и черновиков (LLM-слой)

Читается marketing-агентом на каждом крон-цикле. Правь на лету — следующий тик
работает по-новому. Грубый префильтр (слова/score/возраст) — отдельно, в
`prefilter-config.json`; здесь только семантика.

## Что считать «интересным» (пропускать к черновику)

Пост/сообщение проходит, если ВСЁ верно:
1. Это реальный вопрос или проблема пользователя, где польза Kingside уместна:
   выбор платформы для игры/анализа/пазлов, как улучшаться, разбор позиции,
   инструменты для тренировки, обучение новичка.
2. Ответ можно дать по существу, не рекламно — сначала польза (совет/разбор),
   упоминание Kingside — вторично и органично, максимум одна ссылка.
3. Тред свежий и живой (мало ответов = наш ответ заметят).
4. Нет явного запрета на саморекламу в правилах сабреддита/канала (если правило
   очевидно из контекста — пропусти).

Отбрось молча: мемы, срачи, политика, жалобы без вопроса, уже закрытые темы,
очевидная реклама конкурентов, токсичность, всё где наш ответ будет спамом.

## Как готовить черновик

- Язык — как в исходном сообщении (обычно английский на reddit/x).
- Сначала конкретная польза автору (ответ на его вопрос), потом — если уместно —
  «на Kingside это можно …» с одной ссылкой. Не начинать с рекламы.
- Тон — как живой игрок, не бренд. Без маркетинговых оборотов.
- Длина — короткая, по делу. Никаких «великолепный вопрос!».
- Не выдумывать фичи Kingside — сверяйся с реальным функционалом (apps/web ro).

## Что отправлять на подтверждение

Для каждого прошедшего — `marketing-bot send` с черновиком: ссылка на исходник +
предлагаемый текст ответа. Пользователь одобряет `ok` / правит / `skip`.
Ничего не публикуется без его `ok` (это делает standalone-листенер).
