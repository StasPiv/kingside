# Критерии модерации и черновиков (LLM-слой)

Читается marketing-агентом на каждом крон-цикле. Правь на лету — следующий тик
работает по-новому. Грубый префильтр (слова/score/возраст) — отдельно, в
`prefilter-config.json`; здесь только семантика.

## Гейт ответа — ТОЛЬКО два случая

Пост проходит к черновику, ТОЛЬКО если это одно из:
1. **Явный запрос «где найти / где сделать X»** — человек ищет инструмент,
   сайт, платформу или способ что-то делать (играть, анализировать, решать
   пазлы, тренироваться, учиться). Ключ — он ПРОСИТ куда пойти / чем
   воспользоваться.
2. **Недовольство функционалом** — жалуется, что где-то (chess.com, lichess,
   другое приложение) чего-то не хватает, неудобно, не работает.

Всё остальное — молча мимо. В частности НЕ отвечаем на:
- обсуждение партии/позиции, «как сыграть эндшпиль», «какой ход лучше» — это
  НЕ запрос инструмента, непрошеный шахматный совет = спам;
- общие рассуждения, мемы, срачи, политику, токсичность, закрытые темы;
- рекламу конкурентов, посты самих разработчиков-конкурентов.

Сомневаешься, попадает ли под пункт 1/2 — НЕ отвечай. Лучше пропустить, чем
влезть с неуместным советом.

## Как готовить черновик — один из двух ответов

Определи по `docs/marketing/feature-index.md` (держи в памяти, не читай код
apps/web каждый раз), есть ли у Kingside то, что человек ищет / чего не
хватает. Нужны детали конкретной фичи — дочитай её ADR из индекса:

- **Фича есть** → ответ = ссылка на неё: коротко «на Kingside это здесь: <url>»,
  по-человечески, без рекламных оборотов. Сначала прямой ответ на его запрос,
  ссылка — как решение.
- **Фичи нет** → ответ = «пока такого нет, но планируем реализовать в
  ближайшее время» (мягко, без конкретных обещаний сроков). Показывает, что
  проект живой и слышит запросы.

Правила текста:
- Язык — как в исходном сообщении (обычно английский на reddit/x).
- Тон — как живой участник, не бренд. Никаких «великолепный вопрос!».
- Коротко, по делу, максимум одна ссылка.
- НЕ выдумывать фичи — только то, что есть в feature-index. Нет в индексе —
  вариант «планируем», а не ложь про существующее.

## Что отправлять на подтверждение

Для каждого прошедшего — `marketing-bot send` с черновиком: ссылка на исходник +
предлагаемый текст ответа. Пользователь одобряет `ok` / правит / `skip`.
Ничего не публикуется без его `ok` (это делает standalone-листенер).
