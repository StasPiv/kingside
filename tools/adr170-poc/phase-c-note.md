# ADR-170 рев.4 — фаза C: записка о результате (KS-5014)

Критерий §9: на 3–5 русских запросах-планах по тестовой позиции — возвращает
ли векторный поиск подходящие линии и верна ли их оценка.

**Дерево (§5.1):** первые ходы Maia∪SF-top3 (6 планов: c5, Nd7, a6, Cb4+, Ne7, h6);
вглубь ведёт Maia top-1, развилки Maia top-2 на 2-м и 4-м полуходе; стоп по
D_max=12 / мат / стабильный исход (Maia winProb). **Stockfish (depth 16) + trace
замерены ТОЛЬКО на листьях** (24 линии), не на внутренних узлах. Итог — 24 полные
линии по 12 полуходов.
**Запись (§5.2):** одно осмысленное LLM-описание смысла линии + один вектор Voyage
voyage-3 (dim 1024); `eval`/`outcome_prob`/`subterms` — отдельные поля вне эмбеддинга.
Описание **отталкивается от измеренных подкомпонент sf-trace листа**: берутся
факторы, которыми линия ОТЛИЧАЕТСЯ от среднего по 24 листам (активность фигур, щит
короля, угрозы, форпост, проходная, пространство), сверяются с eval и излагаются
смыслом — без дословного списка id и без домыслов. Общий фон (king_safe_check_*/
king_danger, одинаковый у всех линий) и материал-артефакт середины размена исключены.
Данные — `phase-c.json`, пары «линия+описание» — `lines-with-descriptions.txt`.

---

## Результаты по запросам (топ-5 по косинусу; «лучшая» — по сохранённой оценке для чёрных)

### 1. «надвинуть пешки королевского фланга и атаковать короля»
- В топ-5 есть линия с реальным наступлением на кор. фланге `…h6 Nc3 Cb4 … Nh4 … f4` (+0.56). Остальные — центральные размены.
- Лучшая по оценке из отобранных: `Ne7 Cg5 h6 C:e7 … c5` (−1.47 — сильная контригра чёрных).

### 2. «подорвать пешечный центр белых»
- Топ-5 — линии с подрывом `…c5`/вскрытием центра (в т.ч. `Nd7 O-O c5 c4 …`, `a6 … c5 c4`, `Qb6`-давление).
- Лучшая по оценке: `Ne7 Cg5 h6 Ch4 Qb6 … c5` (−1.31 — перевес чёрных на давлении по d4/b2).

### 3. «разменять фигуры и упростить позицию»
- **Точное попадание:** все топ-5 — разменные/упрощающие линии (`Cg5:e7`, `C:c5`, размены на d4, `Cb4+ Cd2 C:d2`).
- Лучшая по оценке: `Cb4+ Cd2 C:d2 Q:d2 … C:d3` (−0.32).

### 4. «спокойно развить фигуры и рокировать в безопасность»
- Топ-5 — развивающие линии с рокировкой (`…Nc6/Ne7/Nd7`, `O-O`).
- Лучшая по оценке: `Cb4+ Cd2 C:d2 … O-O … c5` (−0.41).

### 5. «начать активную игру на ферзевом фланге»
- Топ-5 — линии с ферзевой активностью (`Qb6`-давление, `…c5`, `c4/Nb5`, `Cb4+`-размены).
- Лучшая по оценке: `Ne7 Cg5 h6 Ch4 Qb6 … c5 … Nc6` (−1.31).

## Различает ли поиск линии (сравнение с прежними ревизиями)

**Да, лучше всех прошлых версий.** Три фактора совпали: (а) линии стали ПОЛНЫМИ
(12 полуходов) — в них реально есть размены, штурмы, подрывы, а не обрубок у корня;
(б) описание — осмысленный разбор смысла линии; (в) один вектор на линию.

- Запрос «размен/упрощение»: топ-5 — именно разменные линии (в рев.2/3 этот запрос
  проваливался — таких линий в коротком дереве не было).
- Запросы «подрыв центра», «ферзевый фланг», «развитие+рокировка»: топ-5 тематически
  связны.
- Кор.-фланговый штурм: релевантная линия (`…Nh4…f4`) попадает в топ-5, но не в топ-1
  — таких «чистых» штурмов Maia от этой позиции даёт мало.

Similarity умеренная (0.29–0.48): линии делят общий дебют (Каро-Канн, продвижение),
поэтому векторы близки — фундаментальное свойство «одна позиция → общий контекст»
(§107-риск снижен описанием «своего», но не снят полностью).

## Вердикт

**Поиск работает.** На полных линиях по §5.1 векторный поиск возвращает тематически
подходящие линии (особенно чётко — размен/упрощение, подрыв центра, ферзевая игра),
оценка отобранных линий берётся из отдельных полей записи (`eval`, `outcome_prob`)
вне эмбеддинга. Замер Stockfish+trace выполнен только на листьях (24 линии), внутри
линий движок не вызывался — ход вели Maia-политики. Остаточная слабость — умеренная
similarity из-за общего дебютного контекста.

# ADR-170 рев.8 — фаза C: вердикт (KS-5015, 26.07)

Сводит работу рев.5→рев.8. Рев.4-вердикт выше оставлен для истории.

## Конвейер рев.8 (что изменилось против рев.4)

- **Ходы дерева ведут ДВЕ тёплые ONNX-сети без поиска в глубину** (тёплый
  python-сервис `nets-oracle.py`, один прогон каждой сети на узел):
  - **Maia-1** (`maia-1500.onnx`, классическая CNN, ELO 1500) — человеческая
    policy. ~1 мс/прогон (против ~26 мс у maia3-трансформера).
  - **Оракул Leela T1** (`t1-256x10.onnx`) — argmax головы политики + WDL. ~7 мс.
  Вход обеих — 112 плоскостей lc0 (энкодер `lc0poc`), декод политики 1858 —
  карта `kAttnPolicyMap`. Из `build-tree.ts` убраны onnxruntime-node и maia-core.
- **Продолжения узла (§5.1 рев.6-8):** Maia top-1 ∪ Maia-ходы ≥0.30 ∪ ход-оракул
  Leela; ширина ≤4; оракул только до D_oracle=6 и ≤K_oracle=2 на линию; ходы
  оракула помечены `engine_only_plies` и защищены от отсечки.
- **Обход** — best-first по вероятности пути Maia с жёсткими пределами
  N_max=1500 / T_max=120 c / L_max=40 и прогрессом в лог.
- **Лист (§5.1 рев.8):** Stockfish `go depth` убран; `eval` = статическая оценка
  форк-trace (`total.v`, перспектива белых), WDL — прогон Leela; subterms — trace.
- **Эмбеддинг (§5.2):** только текст описания (Voyage voyage-3, 1024);
  `moves_san`/`eval`/`outcome_prob`/`subterms` — отдельные поля вне вектора.

## Исходная проблема рев.4/5 и её решение

Рев.4 (фикс. развилки ply 2/4) и рев.5 (порог Maia≥0.30) теряли ход dxc4 40.8%,
т.к. путь к нему идёт через Qxc4 (Maia 1500 ~26%, ниже порога). Оракул Leela
(argmax политики) вводит Qxc4 как объективно сильный ход → линия достигает dxc4.
**Цель достигнута:** в pos2 линии `Rc4 Qxc4 dxc4 Rxd7…` есть (br1/br2/br9),
Qxc4 вошёл оракулом.

## Позиции и объём

- **pos2** `…/2KR3R b` (ферзь d4): 40 линий, 35 оракульных.
- **pos3** `r1bqk2r/… w` (центр c4+d4 vs …e5): 40 линий.
- **pos4** `2rqr1k1/… b` (закрытый центр, штурм f4-g4): 40 линий, 27 оракульных.
Store у каждой — 40 записей × вектор 1024.

## Скорость

Узел ~18 мс (Maia-1 ~1 мс + оракул ~7 мс + издержки). Обход pos3 — 10 c против
112 c на maia3 (×11). Пределы N/T/L защищают от невязки (рев.6 не сходился 10+ мин).

## Результаты фазы C (русские запросы, pos2/pos3/pos4)

Прогнаны запросы: планы сторон; оценка конкретного плана (d5-запирание);
вероятные ошибки; чего опасаться; можно ли e5 сразу; поиск линии с конкретным
ходом; ошибки, ведущие к перевесу соперника.

Находки:
1. **Плановые/концептуальные запросы работают.** «Планы сторон», «e5 сразу или
   готовить», «оцени план d5» — топ-5 тематически релевантен, синтез корректен.
2. **Убранная нотация повышает близость** (0.50 против 0.34 на том же запросе):
   вектор кодирует смысл, а не токены ходов.
3. **Направленность (кому выгодно) косинус не различает.** «Ошибки чёрных →
   перевес белых» вытягивает и линии с перевесом ЧЁРНЫХ — сходство ловит тему
   (ошибка/перевес/вскрытие), не знак. Достоверность даёт `eval`/`WDL` на синтезе.
4. **Поиск конкретного хода слаб** («линия с Bxd5»): вектор-по-тексту не делает
   буквальный поиск — надёжнее фильтр по полю `moves_san`.
5. **Описания с включением статических компонент** (материал, атака на короля,
   безопасность, проходные): сырые subterms в топе — почти константные PSQT, не
   различают линии; информативны ДЕЛЬТЫ к базовой позиции по динамич. факторам —
   их и закладываем в текст.

## Вердикт рев.8

**Фаза C проходит для плановых/концептуальных запросов.** Векторный поиск
сужает 40→5 по смыслу и на плановых запросах возвращает подходящие линии;
финальная достоверность оценки — из полей `eval`/`outcome_prob` вне вектора,
применяемых на шаге синтеза. Ограничения (свойства метода, не дефекты):
поиск конкретного хода — через `moves_san`, а не вектор; направленность оценки
несёт `eval`/`WDL`, а не близость. Цель рев.8 (dxc4 через оракул, без поиска в
глубину) достигнута; конвейер ×11 быстрее рев.4 при 40 линиях на позицию.

Данные: `pos2/`, `pos3/`, `pos4/` (`tree.json` + `descriptions.json` + `store.json`);
код: `build-tree.ts`, `nets-oracle.py`, `build-descriptions.ts`.
