# ADR-170 рев.2 — фаза C: записка о результате (KS-5012)

Критерий §9: на 3–5 русских запросах-планах по тестовой позиции — возвращает
ли векторный поиск подходящие линии и верна ли их оценка в ответе. Оценка глазами.

**Схема (рев.2):** одна запись на линию = **одно описание** (только ходы обеих
сторон, без ярлыков и факторов) + **один вектор** Voyage voyage-3 (dim 1024);
`eval`, `outcome_prob`, `subterms` — отдельные поля, **вне** эмбеддинга.
**Позиция:** `rn1qkbnr/pp3ppp/2p1p3/3pPb2/3P4/5N2/PPP1BPPP/RNBQK2R b KQkq - 1 5`
(база +0.41 в пользу белых, ход чёрных). **База:** 40 линий, глубина ≤4 полухода.
**Фаза C:** запрос → эмбеддинг (input_type=query) → косинус к описаниям → топ-5.
Данные — `phase-c.json`.

---

## Результаты по запросам (топ-5 по косинусу + оценка отобранных линий)

### 1. «надвинуть пешки королевского фланга и атаковать короля»
- Топ-5: `h6 O-O` (0.49), `h6 O-O a6` (0.48), `a6 O-O` (0.47), `c5 O-O cxd4 Nxd4` (0.46), `c5 O-O` (0.46).
- **Ответ:** среди отобранных лучшая по оценке — `c5 O-O` (+0.34); линии с `…h6`
  (пешка h7–h6) — +0.58; вскрытие `c5 O-O cxd4 Nxd4` худшее (+1.18). Верхние места заняли ходы `…h6` — частично релевантно.

### 2. «подорвать пешечный центр белых»
- Топ-5: `h6 O-O` (0.48), `h6 O-O a6` (0.46), `a6 O-O` (0.43), `h6` (0.42), `a6 O-O c5` (0.41).
- **Ответ:** линия с реальным подрывом `…c5` в топ-5 не попала первой — поиск выдал `…h6`/`…a6`. Лучшая по оценке из отобранных — `h6 O-O` (+0.58). **Промах поиска.**

### 3. «разменять фигуры и упростить позицию»
- Топ-5: `c5 c3` (0.37), `c5 O-O` (0.36), `Nd7 c3` (0.36), `Nd7 c3 Bg6` (0.36), `h6 O-O a6` (0.36).
- **Ответ:** чистой разменной линии в базе нет; лучшая по оценке из отобранных — `c5 c3` (+0.34). Similarity низкие (~0.37).

### 4. «спокойно развить фигуры и рокировать в безопасность»
- Топ-5: `h6 O-O a6` (0.32), `h6 O-O` (0.31), `h6 O-O Nd7` (0.31), `Nd7 O-O a5 a4` (0.30), `h6 O-O Ne7` (0.30).
- **Ответ:** линии с рокировкой отобраны верно (все с `O-O`), но развитие `…Nd7/…Ne7` в топе слабо; лучшая по оценке — `h6 O-O` (+0.58).

### 5. «начать активную игру на ферзевом фланге»
- Топ-5: `h6` (0.29), `h6 O-O` (0.28), `a6` (0.28), `Bb4+` (0.27), `c5` (0.26).
- **Ответ:** ферзевый ход `…a6` в отборе есть, но не первый; лучшая по оценке — `c5` (+0.41). Similarity низкие.

---

## Вердикт

**Поиск работает частично, слабее прежней версии.** Причина фактическая: по
рев.2 описание линии — это перечисление ходов обеих сторон («чёрные: пешка идёт
h7–h6; …»), а запрос — интент-уровня («подорвать центр»). Voyage сопоставляет
интент-запрос со списком ходов слабо: similarity 0.26–0.49, верхние места часто
занимают короткие популярные линии (`…h6`, `…a6`), а тематически точная линия
(например `…c5` под «подрыв центра») в топ-1 не выходит.

- Запрос 1 (штурм фланга): частично — топ занят `…h6`, но `…c5` тоже попал.
- Запрос 2 (подрыв центра): промах — `…c5` не в топе.
- Запросы 3–5: слабо, similarity < 0.37, отбор шумный.

Оценка отобранных линий (`eval`, `outcome_prob`) корректна и берётся из отдельных
полей записи, вне эмбеддинга — это соответствует §4 рев.2.

**Итог:** конвейер рев.2 реализован по контракту (одно описание=ходы, один
вектор, оценка/разбиение вне эмбеддинга, поиск топ-5 по косинусу). Качество
семантического поиска на описаниях-ходах низкое — это свойство выбранного
представления (описание без план-лексики), зафиксировано как факт для решения
по продукту.
