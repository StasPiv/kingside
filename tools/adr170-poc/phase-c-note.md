# ADR-170 PoC — фаза C: записка о результате (KS-5011)

Критерий §9: на 3–5 русских запросах-планах по тестовой позиции — возвращает
ли поиск правильные ветки, называет ли ответ верную оценку и причину. Оценка
глазами. Ниже — вход, результаты по 5 запросам, победивший стиль описаний,
вердикт.

**Тестовая позиция:** `rn1qkbnr/pp3ppp/2p1p3/3pPb2/3P4/5N2/PPP1BPPP/RNBQK2R b KQkq - 1 5`
(Каро-Канн, продвижение; ход чёрных; базовая оценка **+0.41** в пользу белых).
**Хранилище:** 40 веток × 3 стиля описаний, эмбеддинги Voyage voyage-3 (dim 1024).
**Конвейер:** запрос → эмбеддинг (input_type=query) → косинус по каждому стилю →
кандидаты из стиля `plan` → ранжирование по сохранённой оценке (ход чёрных: чем
ниже оценка для белых, тем план лучше) + лучшая альтернатива. Данные — `phase-c.json`.

## Результаты по запросам (ответ в форме §7: линии + оценка + причина + альтернатива)

### 1. «надвинуть пешки королевского фланга и атаковать короля»
- **Поиск (plan):** все top-5 — линии с `…h6` (sim 0.50–0.53). Поиск чёткий, план найден верно.
- **Выбор:** `…h6 O-O` — оценка **+0.58** (небольшой перевес белых).
- **Ответ:** типичного пешечного штурма чёрным здесь движок не одобряет: `…h6`
  не решает проблему центра, оценка даже растёт с +0.41 до +0.58. Причина —
  выигрыша по king-факторам чёрные не получают, белые сохраняют щит короля.
- **Лучшая альтернатива (кросс-план):** подрыв центра `…c5` (см. запрос 2) — единственный план, снижающий перевес белых.

### 2. «подорвать пешечный центр белых»
- **Поиск (plan):** все top-5 — линии с `…c5` (sim 0.48–0.53). Верно.
- **Выбор:** `…c5 O-O Nc6 c3` — оценка **+0.29** — наименьший перевес белых среди всех планов.
- **Ответ:** подрыв `…c5` — объективно сильнейший план чёрных в позиции: вскрывает
  центр, чёрные получают подвижность (mobility_queen +0.25) и приближаются к
  равенству. Оценка +0.29 (лёгкий перевес белых).
- **Альтернатива:** `…c5 O-O cxd4` — размен на d4 хуже (**+1.20**): преждевременное вскрытие даёт белым перевес.

### 3. «разменять фигуры и упростить позицию»
- **Поиск (plan):** top-5 размыт — `a6 O-O`, `h6 O-O`, `Nd7`… (sim 0.30–0.34, низко). Чистой разменной линии в дереве **нет**.
- **Выбор:** `…a6 O-O Nd7` — оценка **+0.55**.
- **Ответ:** выраженного форсированного размена в дереве нет — на малой глубине
  Maia/Stockfish его не выбирают. Это осмысленный ответ (§1): «ни сильная, ни
  типичная игра размен здесь не форсируют», а не «плана нет в шахматах».
- **Наблюдение:** самый слабый запрос — низкие similarity подтверждают, что план в дереве не покрыт.

### 4. «спокойно развить фигуры и рокировать в безопасность»
- **Поиск (plan):** top-5 — линии с `…Nd7`/`…Ne7` + рокировка (sim 0.32–0.33). Верно по смыслу.
- **Выбор:** `…Nd7 … Bg6` — оценка **+0.51**.
- **Ответ:** спокойное развитие (`…Nd7`, `…Ne7`, вывод слона, короткая рокировка)
  надёжно, но не борется за уравнение: белые сохраняют +0.5. Крепко, без риска.
- **Альтернатива:** `…Ne7 c3 Ng6` — **+0.76**, пассивнее (конь на g6 не давит на центр).

### 5. «начать активную игру на ферзевом фланге»
- **Поиск (plan):** top-5 — линии с `…a6` (sim 0.34–0.38). Верно.
- **Выбор:** `…a6 O-O Nd7` — оценка **+0.55**.
- **Ответ:** `…a6` с идеей `…b5` — самостоятельная игра на ферзевом фланге;
  оценка +0.55, перевес белых сохраняется. План жизнеспособен, но слабее
  центрального подрыва.
- **Альтернатива:** `…a6 O-O c5` — переход к подрыву центра, но с темповой потерей (**+0.74**).

## Какой стиль описаний ищется лучше

Победитель — **`plan`** (план-обобщение). Обоснование по similarity и чистоте:

| Запрос | raw (top-1 sim) | plan | plan_subterms | верный план найден |
|---|---|---|---|---|
| штурм фланга | 0.40 (шум) | **0.53** (h6) | 0.50 | plan/plan_subterms |
| подрыв центра | 0.42 (шум h6/a6) | **0.53** (c5) | 0.45 | plan/plan_subterms |
| развитие+рокировка | 0.29 | **0.33** | 0.33 | plan/plan_subterms |
| ферзевый фланг | 0.24 | **0.38** (a6) | 0.37 | plan/plan_subterms |

- **`raw`** (сырой пересказ ходов) ищет по совпадению поверхностных токенов ходов —
  выдаёт нерелевантные ветки, для планового запроса не годится.
- **`plan`** даёт самые высокие и чистые совпадения: top-5 стабильно кластеризуется
  вокруг верного плана. Лучший стиль для поиска.
- **`plan_subterms`** близок к `plan`, но добавление лексики подкомпонент немного
  размывает плановый сигнал (similarity ниже). Полезен для «причины» в ответе, не для поиска.

## Вердикт

**Да, поиск работает.** На 4 из 5 запросов стиль `plan` возвращает верный план
чёткими кластерами; оценка в ответе берётся из сохранённого `eval` и корректна.
5-й запрос («размен») намеренно не покрыт деревом — низкие similarity это честно
показывают, что само по себе ценно (различение «плана нет в дереве»).

**Ограничение (для следующей итерации):** «причина из подкомпонент» на малой
глубине слабо различает планы — дельты подкомпонент к корню доминируются общими
king_danger/king_shelter от развития, а не спецификой плана. Рекомендация: (а) для
поиска использовать стиль `plan`; (б) для «причины» в ответе отбирать план-
релевантные подкомпоненты (space, mobility, king_flank_attacks, threat_by_pawn_push),
а не top по модулю дельты; (в) увеличить глубину дерева, чтобы подкомпоненты
успевали разойтись по планам.
