## KS-1931 — Концепция редизайна раздела «Уроки»

**Дата:** 2026-04-26
**Статус:** На обсуждение с пользователем
**Связанные:**
- [ADR-024 Lessons module](../adr/024-lessons-module.md) — фича-родитель
- [ADR-026 User courses](../adr/026-user-courses.md) — пользовательские курсы
- [ADR-030 Lobby latest+authors](../adr/030-user-courses-lobby.md) — discovery-блоки на лобби
- [ADR-031 Lessons lobby redesign](../adr/031-lessons-lobby-redesign.md) — предыдущая итерация редизайна (частично реализована)
- KS-1840 — `MyCoursesBlock`, KS-1890 — `EnrolledCoursesBlock`
- KS-1922 — `LessonsHero` (5 состояний), KS-1923 — pillar+discover, KS-1924 — lazy/skeleton

---

### 0. TL;DR

Это **вторая итерация** редизайна `/lessons`. ADR-031 разобрался с
макроструктурой (hero / personal / curriculum / discovery, выделение
`/lessons/discover`), но **не закрыл** содержательные жалобы пользователя:

- карточки курсов однотипные, без визуальных «крючков» (нет обложек,
  нет понимания сложности/длительности/ЦА);
- «текущий курс» в hero подаётся как «главный», но юзер этого не
  выбирал — несколько активных курсов равноправны;
- блок «открытие уровня Средний» (`LevelGateBanner`) живёт отдельной
  плашкой и считывается как рудимент — он показывает условия, не
  показывая прогресса к ним;
- тексты тизеров слабые / технические / отсутствуют (системный
  каталог сейчас содержит только demo-курс).

Документ — **концепция, не ADR**. Решения по структуре требуют
обсуждения с пользователем до запуска задач.

### 1. Что есть сейчас (фактически)

`apps/web/src/pages/LessonsPage.tsx` рендерит блоки в следующем порядке:

```
<header>          Уроки / Структурированный курс шахмат
<LessonsHero>     Continue / Author / Start / Guest / Loading
<ReviewsDueBlock> SM-2 «к повторению сегодня»
<LevelGateBanner> «Чтобы открыть уровень Средний» (только для beginner)
<MyCoursesBlock>  «Мои курсы» (свои авторские) + CTA «+ Создать»
<EnrolledCoursesBlock> «Курсы, которые я прохожу» (чужие)
<CurriculumPillarBlock> Beginner → Intermediate → Advanced
<CommunityStripBlock>   Compact strip последних community-курсов
```

Что у каждой карточки курса в текущей вёрстке (`CurriculumPillarBlock`,
`EnrolledCoursesBlock`, `MyCoursesBlock`):

- **Заголовок** курса (`titleI18nKey`).
- **Описание** одной строкой (`descriptionI18nKey`) — у системных
  ключей сейчас либо пусто, либо «Технический курс для dev/QA».
- **Счётчик** «N уроков» / «K/N уроков пройдено».
- **Бейдж** «Рекомендуем», «✓ Пройден», «Public/Private».

Чего у карточки **нет** ни в DTO `CourseListItem`, ни в `UserEnrolledCourseDto`
(`packages/shared/src/types/lessons.ts:437`):

- **обложки** (cover image) — нет поля;
- **сложности** (внутри уровня — easy/medium/hard) — нет;
- **длительности** (часов / времени на курс) — нет;
- **целевой аудитории** («для тех, кто играет 1200+», «для детей
  6–10») — нет;
- **превью урока** (мини-доска, FEN-диаграмма) — нет;
- **автора** (для системных) — нет;
- **тегов/тем** (тактика, эндшпиль, дебют) — есть `block.key` на
  уровне урока, но не агрегируется в курс.

LevelGateBanner (`apps/web/src/components/lessons/LevelGateBanner.tsx`)
рендерится отдельной плашкой над `MyCoursesBlock` со списком блокеров
(`course_not_completed`, `puzzle_rating`, `games_played`, `rapid_rating`,
`puzzles_solved`). У плашки нет визуального индикатора прогресса
по этим метрикам — только текст вида «Сыграно партий: 3/20».

> Скрин «до» через playwright сделать не удалось — в окружении
> архитектора `playwright` не установлен. Скрины предыдущей
> итерации лежат в `/tmp/KS-1919/desktop-lessons-full.png` и
> `/tmp/KS-1919/mobile-lobby.png` (ссылки из ADR-031). Опишем
> состояние через анализ кода — этого достаточно для разговора
> о концепции; визуальные скрины «до/после» снимет фронтенд-агент
> в момент реализации.

### 3. Структура страницы

Жалобы №1 и №2 («перегружена», «спутана») — про **группировку**.
Текущая группировка: «мои авторские» / «которые я прохожу» / «системный
каталог» / «community». Юзер не видит **разделения по контракту**:

- Что я **уже начал** (личный фокус, главное).
- Что я **могу пройти** (каталог системных курсов — определённый набор).
- Что мне **рекомендуется** (личная рекомендация на основе уровня).
- Что **создаёт сообщество** (discovery — необязательно).

#### 3.1 Предлагаемая 4-уровневая группировка

```
L1  МОЁ ОБУЧЕНИЕ          ← всё, где есть мой прогресс (равноправно)
    Системный курс A · 3/8 уроков
    Авторский курс B · 1/12 уроков
    Авторский курс C · ✓ пройден
    [Все мои курсы →]      (если > 4 — раскрывается на отдельной странице)

L2  РЕКОМЕНДУЕМ ВАМ        ← персонализированный список
    На основе уровня / последних ошибок
    1–2 карточки максимум

L3  СИСТЕМНЫЙ КУРС         ← структурированный путь Kingside
    Beginner → Intermediate → Advanced
    Прогресс-полоса по всем уровням сразу

L4  СООБЩЕСТВО (compact)   ← strip + ссылка на /lessons/discover
```

#### 3.2 Несколько активных курсов — равноправно или с «главным»?

**Предложение: равноправно, без выделения «главного».**

Аргументы:
- Юзер сам не выбирал «главный курс» — система выбрала за него по
  `lastActivityAt`. Это создаёт ощущение «непрошеного автоответа».
- На разных днях он может хотеть продолжить разные курсы (например,
  утром — теорию эндшпиля, вечером — тактический курс).
- Hero с одной выделенной карточкой — слишком сильное визуальное
  обещание. Если юзер кликнул не туда, ощущение «навязали».

**Решение:**
- Hero **остаётся** для P2 (новый юзер — «Начни с курса для
  начинающих») и P3 (гость — sign-in).
- Для P1 (есть прогресс) hero **становится compact-приветствием**:
  «С возвращением, @user. Ниже — где ты остановился» — без выделения
  одного курса. Под приветствием — секция L1 «Моё обучение» с
  карточками всех активных курсов, **отсортированных по
  `lastActivityAt`**.
- Если активных курсов > 1 — все имеют CTA «Продолжить»; первый по
  свежести получает **бейдж** «Последний раз — 2 дня назад» (это и
  есть подсказка системы, без узурпации выбора).
- Если активный курс **ровно один** — hero может быть L (large) с
  превью урока, как в ADR-031 §4.3. Автоматическое выделение «единственного
  активного» оправдано — нет конкуренции.

#### 3.3 Каталог vs «мои курсы» vs «рекомендации»

| Секция | Что в ней | Откуда данные |
|---|---|---|
| L1 «Моё обучение» | Активные курсы с прогрессом > 0 (любые: системные, чужие, свои) | `userCoursesApi.listEnrolled` + `lessonsApi.listCourses` (фильтр `progress != null`) |
| L2 «Рекомендуем вам» | 1–2 курса по `recommendedLevel` + анализ слабых тем (из puzzle-stats) | `lessonsApi.listCourses` + новый эндпоинт рекомендаций (можно отложить, сначала использовать `recommendedLevel`) |
| L3 «Системный курс» | Полный путь Beginner → Intermediate → Advanced; внутри уровня — компактный список курсов | `lessonsApi.listCourses` (по уровню) |
| L4 «Сообщество» | 4–6 последних community-курсов в strip | `userCoursesApi.listLatest` |

**Что убираем из текущей структуры:**
- Отдельный блок `MyCoursesBlock` (свои авторские курсы) — переезжает
  в **L1**, если у юзера в них есть прогресс. CTA «+ Создать свой
  курс» — отдельная секция-врезка после L1, не блок верхнего уровня.
- `EnrolledCoursesBlock` тоже переезжает в **L1**.
- `LevelGateBanner` — см. §5.
- `ReviewsDueBlock` (SM-2 повторения) **остаётся**, но переезжает в
  L1 как **бейдж** на карточке курса («3 урока к повторению»),
  а не как отдельная плашка. Если повторений > 5 — отдельная карточка
  «Повторения» в L1 рядом с курсами.

### 4. Тизер курса — что в нём должно быть

Сейчас карточка — это «text card»: заголовок + описание + счётчик
уроков. Это работает для каталога из 50+ книг, где обложки путают,
но не работает для каталога из 5–10 курсов, где **главный конкурент
карточки — соседняя такая же карточка**.

#### 4.1 Визуальные элементы (по приоритету)

| Элемент | Зачем | Источник данных | Статус в коде |
|---|---|---|---|
| **Обложка** (1:1 или 16:9) | Главный визуальный «крючок». Обложка — это то, что отличает курс от соседа на расстоянии 2 метров от экрана | `coverUrl: string \| null` | **Нет в DTO** |
| **Заголовок** | — | `titleI18nKey` | Есть |
| **Метка уровня** | Beginner / Intermediate / Advanced | `level` | Есть |
| **Сложность внутри уровня** | 1–3 «звёздочки» или «easy/medium/hard» — внутри одного уровня курсы разной сложности | `difficulty: 1\|2\|3` | **Нет в DTO** |
| **Длительность** | «~ 2 часа», «4 урока» — помогает спланировать сессию | `lessonCount` (есть) + `estimatedMinutes: number` | Частично (только lessonCount) |
| **Целевая аудитория** | «Для играющих от 1200», «Для детей 6+», «После курса „Открытия"» | `audienceI18nKey: string \| null` | **Нет в DTO** |
| **Прогресс** (для активных) | Полоса + счётчик «3/8 уроков» | `progress.lessonsCompleted` | Есть |
| **Бейдж результата** | «✓ Пройден», «3 урока к повторению» | `progress.completedAt`, агрегат от SM-2 | Частично |
| **Ключевые темы** (теги) | 2–3 тега «эндшпиль», «тактика», «короткие партии» — для скана | агрегат `lesson.blockKey` или новое поле `tags: string[]` | **Нет** (есть на уровне урока) |
| **Автор** (для community) | Аватар + nickname | автор из `UserEnrolledCourseDto` | Частично |

#### 4.2 Иерархия размеров (S/M/L)

Реюзаем идею ADR-031 §4.3, но **с обложками**:

- **L (large)** — Hero для P1-single (один активный курс), Hero для
  P2 (CTA «начни с beginner»). Обложка большая (16:9), заголовок крупно,
  CTA primary. **1 на экране максимум.**
- **M (medium)** — карточки в L1 «Моё обучение», L2 «Рекомендуем»,
  L3 «Системный курс». Обложка 4:3 сверху, под ней — заголовок,
  бейджи (уровень, длительность, аудитория), прогресс.
- **S (small)** — strip «Сообщество», горизонтальный scroll. Обложка
  4:3 (компактно), заголовок 2 строки, автор. Без описания, без
  прогресса.

#### 4.3 Mockup карточки M

```
┌──────────────────────────────┐
│                              │
│      [ОБЛОЖКА 4:3]           │
│                              │
├──────────────────────────────┤
│ ⓘ Beginner · ★★☆ · ~2 ч     │  ← бейджи метаданных
│                              │
│ Базовые маты двумя           │  ← заголовок (2 строки макс)
│ ладьями и ферзём             │
│                              │
│ Для тех, кто только          │  ← аудитория (1 строка)
│ начал играть                 │
│                              │
│ ▓▓▓▓░░░░  3/8 уроков         │  ← прогресс (если есть)
│                              │
│ #эндшпиль  #мат              │  ← теги (опционально)
│                              │

└──────────────────────────────┘
```

Для **карточки без прогресса** CTA — «Начать», прогресс-полоса убрана,
вместо неё — длительность («4 урока · ~ 2 часа»).

Для **завершённого курса** — бейдж «✓ Пройден» поверх обложки,
CTA «Повторить» (ведёт в SM-2 повторения, если есть; иначе — на
страницу курса).

#### 4.4 Что нужно от бэка

Поля, которых нет в DTO `CourseListItem` / `Course`:

```ts
interface CourseMeta {
  coverUrl: string | null;          // путь до картинки (или иконка-fallback)
  difficulty: 1 | 2 | 3;            // 1=easy, 2=medium, 3=hard внутри уровня
  estimatedMinutes: number | null;  // оценка времени на весь курс
  audienceI18nKey: string | null;   // i18n-ключ описания ЦА
  tags: string[];                   // ['endgame', 'tactics']
}
```

**Миграция:** добавить колонки в `Course` (Prisma). Заполнить
системные курсы фикстурами в seed. Для пользовательских курсов —
обложка через upload, остальные поля — поля редактора курса.
Это **отдельная backend-задача**, ставится после согласования
концепции.

**Fallback при пустых данных:**
- Нет обложки → плейсхолдер с иконкой шахматной фигуры по уровню
  (пешка / конь / ферзь) + цветовой акцент по уровню.
- Нет `estimatedMinutes` → показываем только `lessonCount`.
- Нет `audienceI18nKey` → строка скрывается, не место не оставляется.
- Нет тегов → строка скрывается.

### 5. Блок «открытие уровня Средний» — что с ним

`LevelGateBanner` в текущем виде — рудимент жёстких unlock-механик
(MMO-style: «вы должны выполнить 5 квестов, чтобы открыть зону»).
В контексте обучения шахматам это работает плохо:

- Курсы Intermediate **не закрыты** — юзер может зайти в любой
  системный курс через `/lessons/<slug>`. Плашка только **советует**.
- Список блокеров («сыграно партий 3/20», «puzzle-рейтинг 1100/1400»)
  смешивает **обучение** и **игру** — у юзера нет времени, ему хочется
  именно сейчас изучить эндшпиль, а не идти играть 17 партий.
- Плашка появляется **только для beginner** (`restrictTo="beginner"`)
  и исчезает при первом же повышении уровня — юзеры со средним
  уровнем её вообще не видят, поэтому она **не образовательная**,
  а только «триггерная».

#### 5.1 Варианты — обзор

**A. Удалить полностью.**
- Плюсы: -1 непонятный блок, страница чище. Все условия повышения
  уровня уезжают в «Профиль / Прогресс» (где они уместнее).
- Минусы: теряется явный сигнал «куда расти». Новички не понимают,
  что они на каком-то уровне, и как с него двигаться.

**B. Удалить плашку, заменить на «прогресс по уровням».**
- В шапке секции L3 «Системный курс» добавить **горизонтальный
  индикатор-таймлайн**:
  ```
  ●━━━━━━━━━━━━━━━━●─ ─ ─ ─ ─ ─ ─ ─ ○─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ○
  Beginner          Intermediate         Advanced
  Ты здесь · 80%    Откроется через      Будет доступен после
                     2 курса              Intermediate
  ```
- Плюсы: показывает **семантику пути**, а не «список квестов». Игровой
  рейтинг не смешивается с обучением — двигаешься по уровням, проходя
  курсы.
- Минусы: требует упрощения логики level-gate (отказаться от
  `puzzle_rating`/`games_played`/`rapid_rating` как блокеров — оставить
  только `course_not_completed` и/или `puzzles_solved`).

**C. Оставить как есть, доработать визуально.**
- Превратить плашку в **карточку с micro-progress** для каждого
  блокера: вместо текста «Сыграно партий: 3/20» — мини-полоса 3/20.
- Плюсы: минимум изменений в backend.
- Минусы: всё равно не решает проблему «зачем мне играть партии
  чтобы открыть курс по эндшпилю» — смесь обучения и игры остаётся.

#### 5.2 Рекомендация — **B**

Семантика «прогресс по уровням сложности» естественнее для раздела
«Уроки», чем «выполни квесты для открытия». Игровой рейтинг
(puzzle/rapid) в обучении логично использовать только как
**рекомендатор** («ты на этом уровне рейтинга — рекомендуем такие
курсы»), но не как **блокер** доступа к курсам.

**Конкретно:**
- Эндпоинт `GET /lessons/level-gate` упрощается: единственный
  блокер — `course_not_completed` для предыдущего уровня. Остальные
  блокеры (`puzzle_rating`, `games_played`, `rapid_rating`,
  `puzzles_solved`) **уезжают** в логику `recommendedLevel` (это уже
  есть, см. `CourseListResponse.recommendedLevel`).
- Плашка `LevelGateBanner` **удаляется**. Её место — **горизонтальный
  level-progress в шапке L3**.
- Текущая логика **не ломает существующих юзеров**: все системные
  курсы доступны и так, плашка только убирала свет с пути.

**Если решение B не подойдёт пользователю** — fallback на A
(удалить полностью). Вариант C считаем антипаттерном: сохраняет
смесь «обучение + игра», которая и есть корень жалобы.

### 6. Тексты тизеров — структура

Сейчас в seed системного demo-курса:
- title: «Демо-курс (TextStep / PuzzleStep / QuizStep)»
- description: «Технический курс для dev/QA: по одному уроку на каждый
  реализованный тип шага плюс смешанный урок. Используется для
  визуальной проверки компонентов уроков.»

Это технические тексты для разработки. Для продакшна **тексты должны
переписываться вместе с появлением реальных курсов** — задача из
зоны chess-expert + редактуры.

#### 6.1 Шаблон описания курса (предложение)

Описание курса разбивается на **3 структурных блока** в DTO, каждый —
отдельный i18n-ключ:

```ts
interface CourseCopy {
  /** Hook — 1 предложение, что юзер научится делать */
  hookI18nKey: string;
  /** Audience — 1 строка «для кого этот курс» */
  audienceI18nKey: string;
  /** Outcome — 1 строка «что будет в финале» */
  outcomeI18nKey: string;
}
```

**Пример заполнения** (для гипотетического курса «Эндшпиль ладья
против короля»):

| Поле | Текст |
|---|---|
| title | «Эндшпиль: ладья против короля» |
| hook | «Научишься загонять одинокого короля в угол ладьёй и королём — приём, который выигрывает каждую вторую блиц-партию.» |
| audience | «Для играющих от 800 рейтинга, кто не знает базовых матов.» |
| outcome | «8 уроков, ~2 часа. После — 5 задач на проверку.» |

**Принципы написания:**

1. **Hook — глагол + результат, не процесс.** Не «изучаем эндшпиль»
   (процесс), а «научишься загонять короля» (результат + действие).
2. **Audience — конкретный признак, не пустые слова.** «Для
   начинающих» бесполезно. «Для играющих от 800 рейтинга, кто не
   знает базовых матов» — конкретно.
3. **Outcome — измеримый результат + объём.** Не «глубокое понимание
   эндшпиля», а «8 уроков, 2 часа, потом 5 задач».
4. **Никакого «маркетингового языка».** Слова «увлекательный»,
   «революционный», «уникальный» в шахматном контексте звучат как
   шум. Шахматистов мотивирует **конкретный навык** + **возможность
   сразу применить**.
5. **Глаголы 2-го лица единственного числа.** «Научишься», не
   «вы изучите». Личный тон, как от тренера.

#### 6.2 Шаблон для пользовательских курсов

Для авторских курсов (`MyCoursesBlock`) тексты пишет сам автор. В
редакторе курса добавить три отдельных поля (с placeholder'ом-шаблоном
выше) вместо одного `description`. **Это backend + редактор —
отдельная задача**, не входит в ADR концепции.

#### 6.3 Какие тексты пересмотреть в первую очередь

Сейчас в системном каталоге **только demo-курс** (`/project/apps/api/src/lessons/seed/courses/demo`).
Реальных системных курсов ещё нет. Это значит:

- **Тексты тизеров — задача chess-expert**, не frontend/архитектора.
  Создание реальных системных курсов и их описаний — отдельный поток
  работ, идёт параллельно.
- Шаблон выше — **для chess-expert**, чтобы при наполнении контента
  у курсов сразу была единая структура.

#### 7.3 Mobile

Принципы те же, что в ADR-031 §5.3:
- L1, L2, L4 — **горизонтальный scroll** карточек.
- L3 — **вертикальный**, потому что это «main offer».
- Hero compact-приветствия — 2–3 строки текста, занимает ½ экрана.

### 8. Что нужно от backend (на согласование)

Если концепция принимается, backend-задача добавляет в DTO `Course`:

```prisma
model Course {
  // ... существующие поля
  coverUrl         String?   // путь к обложке
  difficulty       Int       @default(2) // 1=easy, 2=medium, 3=hard
  estimatedMinutes Int?      // оценка времени
  audienceI18nKey  String?
  hookI18nKey      String?   // выделить из текущего descriptionI18nKey
  outcomeI18nKey   String?
  tags             String[]  // ['endgame', 'tactics']
}
```

**Миграция:**
- Добавить колонки (все nullable / с дефолтами — обратная совместимость).
- В seed-фикстурах (`apps/api/src/lessons/seed/courses/`) для
  существующих курсов заполнить новые поля.
- Старое `descriptionI18nKey` сохранить как **fallback** для UI, если
  новые поля пусты.

**Эндпоинт level-gate** упрощается:
- `GET /lessons/level-gate` — только блокер `course_not_completed`.
- Остальные блокеры (`puzzle_rating`, `games_played`, `rapid_rating`,
  `puzzles_solved`) — оставляем в логике `recommendedLevel` либо
  удаляем (после согласования с chess-expert).

**Эндпоинт рекомендаций** (необязательно для MVP):
- `GET /lessons/recommended` — 1–2 курса по уровню + слабые темы из
  puzzle-stats. На MVP фронт берёт `recommendedLevel` + случайный
  выбор из этого уровня.

### 9. Решения, требующие обсуждения с пользователем

Прежде чем декомпозировать в задачи исполнителям — нужно
зафиксировать **3 ключевых развилки**:

1. **Hero для P1 — compact-приветствие или продолжать выделять один
   курс L?**
   Концепция предлагает compact (см. §3.2). Альтернатива — оставить
   L-карточку «Continue» с явной плашкой «Ты последний раз был здесь
   2 дня назад». Пользователю — что больше нравится?

2. **LevelGateBanner — удалить полностью или превратить в
   горизонтальный таймлайн?**
   Концепция предлагает таймлайн (§5.2 вариант B). Если пользователь
   считает «у нас ещё нет реального Intermediate-контента, не нужно
   обещать» — fallback на A (удалить).

3. **Поля `coverUrl`/`difficulty`/`audienceI18nKey`/`tags` —
   добавляем сейчас или делаем визуальный редизайн на текущих DTO с
   заглушками?**
   Концепция предлагает добавить — без обложек редизайн карточек
   теряет смысл. Альтернатива — пилотный редизайн на 2–3 системных
   курсах с обложками (картинки в `apps/web/public/`), а DTO
   расширяем потом.

### 10. Что НЕ входит в эту концепцию

- **Реализация (код)** — это документ-обсуждение. Задачи для
  frontend/backend/layout создаёт координатор после согласования.
- **Аналитика и метрики успеха** — задача marketing-агента (см.
  ADR-031 §8 — уже описаны базовые метрики).
- **Контент системных курсов** — задача chess-expert. Эта концепция
  даёт только шаблон для текстов (§6.1).
- **Анимации и hover-эффекты** — зона layout.
- **Пользовательские курсы (`MyCoursesBlock`/редактор)** — не
  затрагиваем глубоко, только перемещаем в L1 и упоминаем поля
  `hook/audience/outcome` в редакторе как отдельную задачу.
- **Discover-страница `/lessons/discover`** — не пересматриваем,
  она работает по ADR-031 §3.
