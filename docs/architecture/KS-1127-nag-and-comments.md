# KS-1127: Пометки (NAG) и комментарии к ходам в анализе

## 1. Текущее состояние

### Что есть
- `ChessMove` — linked list с поддержкой вариаций (`variations: ChessMove[][]`)
- `PgnDeserializer` — парсит PGN, но **удаляет** комментарии `{...}` и `;...`
- `PgnSerializer` — сериализует дерево ходов в PGN без аннотаций
- `ReviewMoveList` — отображает ходы с вариациями, контекстное меню (promote/delete/truncate)
- Хранение: поле `pgn TEXT` в таблицах `Analysis` и `GameAnalysis`

### Что отсутствует
- NAG (Numeric Annotation Glyphs) — не парсятся, не хранятся, не отображаются
- Текстовые комментарии — удаляются при парсинге PGN

## 2. Стандарт PGN: NAG и комментарии

### NAG (Numeric Annotation Glyphs)
В PGN формате NAG записываются как `$N` после хода:

| NAG | Символ | Значение |
|-----|--------|----------|
| $1  | !      | Хороший ход |
| $2  | ?      | Плохой ход |
| $3  | !!     | Отличный ход |
| $4  | ??     | Грубая ошибка |
| $5  | !?     | Интересный ход |
| $6  | ?!     | Сомнительный ход |
| $7  | □      | Вынужденный ход |
| $10 | =      | Равная позиция |
| $13 | ∞      | Неясная позиция |
| $14 | ⩲      | Небольшое преимущество белых |
| $15 | ⩱      | Небольшое преимущество чёрных |
| $16 | ±      | Преимущество белых |
| $17 | ∓      | Преимущество чёрных |
| $18 | +−     | Решающее преимущество белых |
| $19 | −+     | Решающее преимущество чёрных |

Пример PGN: `1. e4 $1 {Отличное начало} e5 $6 2. Nf3`

### Комментарии
- Блочные: `{текст комментария}` — после хода
- Строчные: `; текст до конца строки` — не используем (устаревший формат)

## 3. Модель данных

### 3.1 Расширение ChessMove (frontend)

```typescript
// apps/web/src/review/types.ts
export interface ChessMove {
  // ... существующие поля ...
  nags?: number[];      // массив NAG кодов, например [1] для "!"
  comment?: string;     // текстовый комментарий
}
```

Одно поле `nags: number[]` — стандартный подход. На ход может быть несколько NAG (например, ход `$1` и оценка позиции `$14`).

### 3.2 Хранение в БД

**Изменений в схеме БД не требуется.** NAG и комментарии сериализуются в PGN строку и хранятся в существующих полях:
- `Analysis.pgn` (TEXT)
- `GameAnalysis.analysisPgn` (TEXT)

Это стандартный подход — PGN формат нативно поддерживает NAG и комментарии, дополнительные таблицы/колонки не нужны.

### 3.3 Изменений в API не требуется

Текущие эндпоинты (`PUT /api/analyses/:id`, `PUT /api/games/:id/analysis`) уже принимают PGN как текст. NAG и комментарии будут частью PGN строки.

## 4. Парсинг и сериализация PGN

### 4.1 PgnDeserializer — доработка

Текущий код удаляет комментарии:
```typescript
// БЫЛО:
.replace(/\{[^}]*\}/g, ' ')  // удаляет комментарии
```

Нужно:
1. Извлекать комментарии `{...}` как токены и привязывать к предыдущему ходу
2. Распознавать NAG токены (`$1`, `$2`, ... или символы `!`, `!!`, `?`, `??`, `!?`, `?!`)
3. Присваивать `nags` и `comment` соответствующему `ChessMove`

### 4.2 PgnSerializer — доработка

После SAN хода добавлять:
1. NAG: `$1`, `$3` и т.д.
2. Комментарий: `{текст}`

Пример вывода: `1. e4 $1 {Отличное начало} e5 $6 2. Nf3`

## 5. UI: отображение и редактирование

### 5.1 Отображение NAG в списке ходов

NAG символы отображаются сразу после SAN хода, выделены цветом:
- `!`, `!!` — зелёный
- `?`, `??` — красный
- `!?`, `?!` — оранжевый
- `□` — серый
- Оценки позиции (`=`, `±`, `∓` и т.д.) — серый, мельче

Пример: `1. e4! e5?! 2. Nf3`

### 5.2 Отображение комментариев в списке ходов

Комментарий показывается как отдельный блок между ходами:
- Шрифт меньше, курсив, приглушённый цвет
- Если длинный — обрезается с `...`, раскрывается по клику
- Максимальная высота в свёрнутом состоянии: 2 строки

### 5.3 Добавление/редактирование NAG

**Способ**: контекстное меню хода (уже существует для promote/delete/truncate).

Добавить в контекстное меню секцию "Annotate":
- Список кнопок NAG: `!` `!!` `?` `??` `!?` `?!` `□`
- Клик по NAG — toggle (добавить/убрать)
- Активный NAG визуально выделен

### 5.4 Добавление/редактирование комментария

**Способ**: через то же контекстное меню, пункт "Add comment" / "Edit comment".

По клику открывается inline textarea под ходом (или модальное окно на мобиле):
- Автофокус
- Сохранение по blur или Enter
- Кнопка удаления комментария (очистить и закрыть)

### 5.5 Мобильная версия

- Long-press на ходе → контекстное меню (уже реализовано)
- NAG кнопки и комментарий — в том же bottom sheet

## 6. useReviewState — новые actions

```typescript
// Новые actions в reducer:
SET_NAG:     { globalIndex: number, nags: number[] }
SET_COMMENT: { globalIndex: number, comment: string }
```

Эти actions находят ход по `globalIndex` в дереве (через `searchInHistory`) и обновляют его `nags`/`comment`. После изменения — пересериализация в PGN и автосохранение через `useAnalysisPersistence`.

- Позиционные оценки в NAG ($10-$19) — можно добавить позже

- Экспорт аннотированного PGN в файл (уже работает через существующий export, NAG и комментарии будут в PGN автоматически)
- Синхронизация аннотаций между устройствами (уже работает через существующий механизм сохранения)
