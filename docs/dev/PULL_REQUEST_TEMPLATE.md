## Добавляешь новое правило контекстных подсказок (hints)?

Если в PR появляется новое правило в таблице `hints` (или меняется DSL/тексты существующего) — обязательно **4 артефакта в одном PR** (ADR-150, гайд `docs/dev/hints-test-workflow.md`):

- [ ] Правило заведено через `POST /admin/hints` (либо `PATCH` для существующего). В описании PR указан `key`.
- [ ] **Backend-фикстура** `apps/api/test/hints-fixtures/<key>.ts` с `RuleFixture` (`matches` + `noMatch` сценарии).
- [ ] **E2E-сценарий** `tools/e2e-hints/tests/<key>.spec.ts` — минимум один позитивный и один негативный кейс.
- [ ] **i18n ru/en** заполнены человеческими текстами в `i18n.ru.{title,body,ctaLabel?}` и `i18n.en.{title,body,ctaLabel?}` (не машинный перевод).
- [ ] **Anchor существует в DOM** — проверено `npx playwright test --headed tools/e2e-hints/tests/<key>.spec.ts` на профиле `test-hints`.
- [ ] Если требуется новый anchor — добавлен `data-hint-anchor="..."` в JSX (одна строка, **без** правок `packages/shared` — ADR-148).
- [ ] Если `targetActorTypes` включает `guest` — Playwright использует `loginAsGuest`, не `loginAs`.

Если **меняется** существующее правило:

- [ ] Обновлены фикстура `apps/api/test/hints-fixtures/<key>.ts` и e2e-сценарий — отражают новую логику.
