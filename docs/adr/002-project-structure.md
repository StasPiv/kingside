# ADR-002: Структура проекта

**Статус:** Принято
**Дата:** 2026-03-07
**Контекст задачи:** KS-6

## Контекст

Необходимо определить, как организовать кодовую базу: монорепо, отдельные репозитории или монолит.

## Решение

### Монорепо с разделением на пакеты

```
kingside/
├── apps/
│   ├── api/            # NestJS бэкенд
│   └── web/            # React фронтенд
├── packages/
│   └── shared/         # Общие типы, константы, утилиты
├── docs/
│   ├── adr/
│   └── architecture/
├── package.json        # Корневой (workspaces)
└── turbo.json          # Turborepo для оркестрации
```

### Оркестрация: Turborepo

- Параллельные сборки, кэширование
- Простая настройка npm workspaces
- Минимальный overhead по сравнению с Nx

### Пакет `shared`

Содержит:
- TypeScript-типы для API (request/response DTO)
- Типы WebSocket-событий
- Шахматные константы (начальная позиция, правила таймконтролей)
- Утилиты валидации, общие для клиента и сервера

## Альтернативы

| Вариант | Причина отказа |
|---------|----------------|
| Отдельные репозитории | Сложнее синхронизация типов, overhead для одного разработчика |
| Единый монолит (без разделения) | Затрудняет масштабирование, смешивает ответственности |
| Nx | Избыточен для проекта такого масштаба |

## Последствия

- Общие типы гарантируют консистентность API между клиентом и сервером
- Turborepo добавляет зависимость, но экономит время на сборках
- Один `git clone` — весь проект готов к работе
