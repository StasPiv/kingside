# ADR-005: Выбор библиотеки локализации

**Статус:** Принято
**Дата:** 2026-03-07
**Контекст задачи:** KS-39

## Контекст

Интерфейс Kingside содержит захардкоженные строки на русском языке. Необходимо добавить поддержку нескольких языков (английский по умолчанию, русский). Язык выбирается пользователем в настройках и сохраняется на сервере.

## Решение

### react-i18next

- Де-факто стандарт для i18n в React-приложениях
- Основан на i18next — зрелой библиотеке с большим сообществом
- Хук `useTranslation()` для функциональных компонентов
- Поддержка интерполяции, плюрализации, вложенных ключей
- Статические JSON-файлы переводов — bundled вместе с приложением (нет необходимости в lazy loading при двух языках)

## Альтернативы

| Библиотека | Причина отказа |
|------------|---------------|
| react-intl (FormatJS) | Более тяжеловесная, избыточна для двух языков |
| LinguiJS | Меньше сообщество, сложнее настройка |
| Кастомное решение | Нет смысла при наличии зрелых библиотек |

## Хранение выбранного языка

- **Сервер**: поле `locale` в таблице `User` (PostgreSQL)
- **Клиент**: при авторизации — из профиля пользователя; для гостей — `navigator.language` с fallback на `"en"`
- Не используем localStorage для хранения языка — источник правды на сервере

## Последствия

- Новые зависимости: `i18next`, `react-i18next`
- Необходим рефакторинг всех компонентов: замена строковых литералов на вызовы `t()`
- Миграция БД для добавления поля `locale`
- При добавлении нового языка — только новый JSON-файл переводов
