# ADR-164: Анализ позиции словами с вариантами — комбинация Maia и Stockfish

**Дата:** 2026-07-13
**Статус:** Предложено
**Задача:** KS-4937
**Связанные ADR:** 108/108b (AI-комментарий позиции, UX), 096–099 (Maia в панели анализа), 124 (maia-core консолидация), 102/103/107 (LLM-конвейер factors)

---

## 1. Контекст

Запрос пользователя: комментарий позиции должен говорить **вариантами** — «человек здесь сыграет X, но это проваливается из-за Y; ключ — Z», а не только статикой факторов. Прототип контура проверен вручную (marketing, /tmp/maia-sf-comment-flow.md): FEN → Maia-3 топ-5 человеческих ходов с вероятностями → каждый кандидат прогоняется Stockfish'ем → текст «ловушка → почему нет → ключ». Главное правило прототипа: **ни одного хода в тексте без прогона движком** — дважды пойманная ошибка дня были линии «по памяти».

Решение пользователя (13.07, web): **Maia и Stockfish считаются на клиенте.**

Что уже есть и переиспользуется:

| Компонент | Где | Роль в фиче |
|---|---|---|
| Maia-3 ONNX в браузере | `useMaiaAnalysis` + `packages/maia-core` (browser provider), модель `apps/web/public/maia3/` | Топ-N человеческих ходов с вероятностями; ELO уже настраивается пользователем (`analysis.maia.elo`, localStorage) |
| Stockfish 18 WASM | `useStockfish` (multipv, `go movetime`, searchmoves) | Оценка и pv каждого кандидата |
| LLM-контур | `POST /analyses/position/comment` (ADR-108): rate-limits, кэш по FEN, i18n ru/en, 7 состояний UI | Расширяется полем `variants` |
| Серверные Maia/SF-trace | `position-comment/maia.service.ts` (ForcedLineRoller), `factors-rebuilder` (форк SF-trace) | Остаются как есть — форсированная прокатка и пересборка factors не меняются |
| UI-панель | `AiPositionCommentPanel` + `useAiPositionComment` | Точка входа расширяется, не дублируется |

## 2. Решение: где считается

**Клиент.** Аргументы (помимо прямого решения пользователя):
1. На странице анализа оба движка уже загружены и часто уже работают — ноль новой загрузки.
2. Инвариант KS-2433 «поисковый движок не живёт на сервере» сохраняется (серверный SF-trace — eval-проба, не поиск; ForcedLineRoller — только Maia).
3. KS-4923: endpoint и так держит HTTP 5–21 с на LLM; +5 поисков SF на сервере удлинили бы ответ и съели CPU общего сервера. На клиенте сбор вариантов идёт ДО запроса, серверное время не растёт.
4. Персонализация бесплатно: Maia-ELO берётся из существующей настройки пользователя — «человеческие ходы» соответствуют его уровню.

Минус (фиксируем честно): скорость и качество проб зависят от устройства пользователя; на слабом мобильном сбор 5×2 с — ощутимая пауза. Митигируется прогрессом в UI и настраиваемым `movetime`.

## 3. Конвейер

```mermaid
sequenceDiagram
    participant U as Пользователь
    participant H as useVariantProbes (новый хук)
    participant M as Maia WASM (useMaiaAnalysis)
    participant S as SF18 WASM (useStockfish)
    participant API as POST /analyses/position/comment
    participant W as LLM-webhook

    U->>H: «Оценка с вариантами»
    H->>M: predictMoves(fen, elo)
    M-->>H: топ-N ходов + вероятности (N=4)
    loop каждый кандидат
        H->>S: position fen moves <ход>; go movetime 2000
        S-->>H: eval (cp/mate) + pv (первые 6 полуходов)
    end
    H->>API: { fen, factors, language, variants[] }
    API->>API: chess.js-валидация легальности линий
    API->>W: prompt: factors + блок вариантов + правило «только эти ходы»
    W-->>API: текст «ловушка → почему нет → ключ»
    API-->>U: { comment }
```

Контракт `variants` (packages/shared, меняет backend):

```ts
interface PositionVariantProbe {
  uci: string;            // ход-кандидат
  san: string;
  humanProb: number;      // вероятность Maia (0..1), elo из настройки
  evalCp: number | null;  // оценка после хода (cp, с точки зрения ходившего)
  mateIn: number | null;
  pv: string[];           // uci, ≤6 полуходов — рефутация/продолжение
  movetimeMs: number;     // сколько думал SF (честность пробы)
}
// В UpdatePositionCommentRequest: variants?: PositionVariantProbe[] (≤6)
// + maiaElo?: number — для регистра текста («на вашем уровне часто играют…»)
```

Параметры сбора: N=4 кандидата (`humanProb ≥ 0.05`), `movetime` 2000 мс на кандидата (≈8–10 с суммарно), pv усечён до 6 полуходов. Прогон последовательный (один WASM-инстанс), прогресс в UI «Проверяю варианты 2/4». Константы — в конфиге хука, не в ADR-камне.

## 4. Backend: изменения position-comment

1. DTO: `variants` (optional, `@ArrayMaxSize(6)`, class-validator вложенный), `maiaElo` (optional).
2. **Валидация фактов, без движка:** каждая линия `fen + uci + pv` проверяется chess.js на легальность; нелегальная — отбрасывается с логом (защита от мусора клиента). Сервер движком ничего не пересчитывает.
3. Согласование с ForcedLineRoller: если прокатка сыграла ходы (finalFen ≠ fen), присланные варианты описывают ИСХОДНУЮ позицию → в этом случае `variants` в prompt НЕ включаются (лог + текст без вариантов). Правки роллера не требуется; кейс редкий (прокатка срабатывает при maiaProb ≥ 0.99).
4. Prompt (обе локали): блок «Вероятные человеческие ходы (уровень ~{elo}): {san} ({prob}%) → оценка {eval}, продолжение {pv-san}…» + жёсткие правила: упоминать ходы ТОЛЬКО из блока и их pv; структура «ловушка → почему проваливается → сильнейший ход»; не называть источник «engine/Maia» в тексте.
5. Лимиты, таймауты, кэш, 429 — без изменений (ADR-108 §6). Запрос с вариантами — тот же 1 запрос квоты.

## 5. UX-точка входа

Расширяется существующая `AiPositionCommentPanel` (ADR-108 §3) — новая панель не заводится:
- Рядом с кнопкой «Получить оценку от AI» — чекбокс/переключатель «с вариантами» (состояние в localStorage, по умолчанию **вкл**, если SF и Maia доступны в сессии).
- При включённом режиме `request()` сначала собирает пробы (стадия `probing`, прогресс «Проверяю варианты 2/4», отменяемо), затем существующий `loading`.
- Maia или SF недоступны (WASM не загрузился) → переключатель disabled с подсказкой, кнопка работает по-старому. Answer-деградация симметрична серверной: без вариантов, не ошибка.
- Кэш-ключ дополняется признаком `withVariants` — оценки «со» и «без» вариантов не перетирают друг друга.

## 6. Декомпозиция

| # | Задача | Владелец | Содержание | Зависит от |
|---|---|---|---|---|
| 1 | Контракт + prompt | backend | `PositionVariantProbe` в shared, DTO+валидация легальности (chess.js), блок вариантов в system-prompt (ru/en), правило «только присланные ходы», пропуск блока при сработавшей прокатке, spec-тесты | — |
| 2 | Сбор проб на клиенте | frontend | Хук `useVariantProbes` (Maia топ-N → последовательные SF-пробы movetime 2000, отмена через AbortController/stop), состояние `probing` в `useAiPositionComment`, кэш-ключ `withVariants` | 1 (типы) |
| 3 | UI режима | frontend | Переключатель «с вариантами» в `AiPositionCommentPanel`, прогресс проб, disabled-состояния, i18n `analysis.aiComment.variants.*` | 2 |
| 4 | Приёмка | qa | Desktop+mobile: текст ссылается только на присланные ходы; отмена на стадии проб; WASM недоступен → деградация; нелегальная линия (mock) отброшена сервером; кэш со/без вариантов раздельный | 1–3 |

Задачи 2–3 может нести один исполнитель подряд; критический путь — 1 → 2 → 3 → 4.

## 7. Отклонённые альтернативы

- **Счёт Maia+SF на сервере** (как в прототипе marketing) — решение пользователя «клиентские движки»; плюс: сервер один и слабый, поиск 5×movetime на запрос не масштабируется, инвариант KS-2433, latency поверх и так длинного LLM-запроса (KS-4923).
- **Серверная валидация вариантов движком** («перепроверить eval клиента») — возвращает поиск на сервер; легальность линий chess.js покрывает угрозу мусора, а неточный eval клиента портит только регистр текста, не корректность ходов.
- **Отдельная кнопка/панель «Разбор вариантов»** — дублирует ADR-108-панель, две сущности «AI-оценка» путают; режим-переключатель дешевле и найдётся.
- **Стриминг/асинхронный endpoint** — вне scope, синхронный паттерн подтверждён (KS-4923: шлюз выровнен до 180 с); сбор проб на клиенте не увеличивает серверное время.
- **Maia-вероятности с сервера (MaiaService)** — сервер знает только фиксированный ELO 2400 для прокатки; клиентская Maia уже персонализирована настройкой пользователя.
