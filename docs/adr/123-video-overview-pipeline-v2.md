# ADR-123: Конвейер производства видеообзоров (серия) — синхронизация дикторской дорожки и кадра через посимвольные тайминги ElevenLabs

**Статус:** Принято к реализации (решение пользователя по KS-4062: подход «аудио первично» + словa-якоря).
**Дата:** 2026-06-12
**Задача:** KS-4062 (выработка решения), последующие задачи на devops + QA — будут заведены координатором отдельно.
**Связанные документы:** [video-overview-series.md](../architecture/video-overview-series.md), [pipeline-v2.md](/tmp/KS-4062/pipeline-v2.md) (рабочий черновик, после принятия — переезжает в `docs/architecture/video-overview-pipeline.md`).

## 1. Контекст

### 1.1 Что есть сейчас

Сначала записывается видео под piper-черновик (см. `tmp/KS-4055/`, `tmp/KS-4061/`, `tmp/KS-4062/`), потом дорожку заменяют на финальный голос (ElevenLabs, Artlist). При каждой замене озвучки возникает рассинхрон — действия Playwright привязаны к секундным меткам piper-длительности, не к словам диктора.

Конкретные точки рассинхрона:
- В `record.mjs` все действия — линейный поток `wait(N)` от старта записи (`recordStartedAt`). Тайминги жёстко зашиты под piper-длительности конкретного запуска.
- `narration-timeline.json` (placements) фиксируется ПОСЛЕ съёмки и не пересчитывается при замене mp3.
- `segments.json`, `scene-actions`, текст диктора и видео хранятся в разных файлах без явной связи. Любое изменение одной части — ручная пересинхронизация трёх–четырёх артефактов.
- Результат: каждая итерация правок занимает часы и плодит итерации (см. историю KS-4062 — v3, v7, v9, v10, v11).

### 1.2 Что хочет пользователь

Воспроизводимый процесс: одобрил текст → получил готовое видео без ручной подгонки. Правка одного сегмента — не пересъёмка всего на смысловом уровне, автоматическая ре-синхронизация на техническом.

### 1.3 Что НЕ в области решения

- Подбор voice_id и пресета голоса (stability, similarity) — решение пользователя один раз на серию.
- Музыкальное оформление, HUD-стили, splash-экраны — за рамками синхронизации.
- Изменение сценария на лету: если архитектор меняет шаги, `scene-actions.json` обновляется вручную (меняются Playwright-локаторы и порядок взаимодействия с UI). Автоматизировать это нельзя.

## 2. Решение

### 2.1 Три инварианта

**И1. Аудио первично.** Финальная озвучка генерируется ДО записи видео. Длительность каждого сегмента — единственный авторитетный источник тайминга. Сцена видео удерживается ровно `durMs[i] + BUFFER_MS` (400 мс, текущее значение).

**И2. Сегмент атомарен.** Один сегмент = один шаг сценария = одна сцена видео = один файл mp3. Замена одного сегмента не требует пересъёмки соседних на смысловом уровне.

**И3. Действия привязаны к словам-якорям.** В декларативном `scene-actions.json` действие описывается как `{"anchor": "Пуля", "type": "hover", "selector": "...", "leadMs": -300}`. ElevenLabs API возвращает посимвольные тайминги (`character_start_times_seconds` в endpoint `/v1/text-to-speech/{voice_id}/with-timestamps`); `record.mjs` сам вычисляет момент каждого действия как `sceneStartMs + anchorMs + leadMs`.

При замене озвучки посимвольные тайминги меняются → действия автоматически переезжают на новые позиции. Конвейер идемпотентен.

### 2.2 Восьмишаговый конвейер

| Шаг | Кто запускает | Вход | Выход |
|---|---|---|---|
| 1. Сценарий | архитектор | требования к разделу | `scenario-vN.md` |
| 2. Тексты диктора | архитектор | сценарий | `segment-NNN.txt` (по одному на сцену) |
| 3. Декларация действий | архитектор + QA | сценарий | `scene-actions.json` |
| 4. **Синтез озвучки** | QA (скрипт) | тексты + ELEVENLABS_API_KEY | `NN.mp3` + `NN.timestamps.json` |
| 5. Замер длительностей | QA (скрипт) | mp3 | `segments.json` (durMs) |
| 6. Запись видео | QA | scenario, scene-actions, segments, timestamps | `videos/*.webm` + `placements.json` |
| 7. Сборка дорожки | QA (скрипт) | mp3 + placements + общая длина | `voice.wav` |
| 8. Финальный микс | QA (скрипт) | videos + voice.wav | `<slug>.webm` |

Единственная точка фиксации тайминга — **шаг 4** (синтез ElevenLabs). Все последующие шаги — функции от его выхода.

### 2.3 Контракт `scene-actions.json`

```json
{
  "ticket": "KS-NNNN",
  "scenarioVersion": "vN",
  "defaults": {"leadMs": -200, "occurrence": 1, "side": "A"},
  "scenes": [
    {
      "tag": "play-page",
      "segment": 1,
      "metaActions": [
        {"type": "goto", "url": "${WEB}/play", "side": "A"},
        {"type": "waitForSelector", "selector": ".play-page__title", "side": "A"}
      ],
      "actions": [
        {"anchor": "«Пуля»", "type": "hover", "selector": "button:has-text('Пуля')", "leadMs": -300},
        {"anchor": "«Блиц»", "type": "hover", "selector": "button:has-text('Блиц')", "leadMs": -300}
      ]
    }
  ]
}
```

Типы действий: `hover`, `click`, `type` (составное click+fill), `drag` (для доски, dragSquare), `flash` (короткая CSS-подсветка), `goto`, `waitForSelector`, `dismissOnboarding` + спец-действия для двухконтекстной съёмки (`startContextB`, `contextBJoinQueue`, `waitForBothNavigate`, `detectColors`).

Поля действия:
- `anchor` — точная подстрока из текста сегмента (поиск по первому/N-му вхождению);
- `occurrence` — какое вхождение брать (по умолчанию 1);
- `useLast: true` — брать последнее вхождение независимо от `occurrence`;
- `leadMs` — сдвиг от начала якоря (отрицательное = раньше, положительное = позже);
- `fallbackAtMs` — резервное время, если якорь не найден (относительно начала сцены; отрицательное = от конца);
- `delayFromPrevMs` — относительная задержка от предыдущего действия (используется когда якорь не нужен, например для ритмичных ходов в партии);
- `side` — `A` или `B` для двухконтекстной съёмки.

### 2.4 Алгоритм разрешения якоря

```
1. Склеить timestamps.characters в одну строку = fullText
2. Найти все позиции anchor в fullText (точное совпадение подстроки)
3. Выбрать вхождение по occurrence (или последнее при useLast=true)
4. atMs = round(timestamps.character_start_times_seconds[pos] * 1000)
5. Если anchor не найден — применить fallbackAtMs (если задан) либо ошибка
```

### 2.5 Изменения в `record.mjs`

**Убрать:**
- Все линейные `wait(N)` от старта записи (текущий /tmp/KS-4062/record.mjs, строки 256–442).
- Жёстко зашитые тайминги действий.

**Вернуть и расширить** scene-based архитектуру (скелет уже есть в record.mjs:52-63, но не используется в основном потоке):

```js
async function scene(refPage, tag, actionFn) {
  const s = segByTag[tag];
  const startMs = Date.now() - recordStartedAt;
  await actionFn();
  const need = s.durMs + BUFFER_MS;
  const spent = Date.now() - recordStartedAt - startMs;
  if (spent < need) await refPage.waitForTimeout(need - spent);
  placements.push({tag, startMs, durMs: s.durMs, holdMs: Date.now() - recordStartedAt - startMs});
}

async function runActions(tag) {
  const sceneActs = sceneActionsByTag[tag] || [];
  const ts = timestampsByTag[tag];
  const scheduled = resolveAnchors(sceneActs, ts).sort((a, b) => a.atMs - b.atMs);
  let cursor = 0;
  for (const a of scheduled) {
    const wait = Math.max(0, a.atMs - cursor);
    if (wait > 0) await pageA.waitForTimeout(wait);
    cursor = a.atMs;
    await dispatchAction(a);
  }
}
```

Основной поток сводится к последовательным `await scene(pageA, tag, () => runActions(tag))`.

`record.mjs` становится универсальным интерпретатором — общим для всей серии. Под конкретный тикет меняются только три файла: `scenario-vN.md`, `scene-actions.json`, содержимое `/tmp/voiceover/KS-XXXX/`.

### 2.6 Где живёт код

| Артефакт | Путь | Когда коммитим |
|---|---|---|
| Универсальный `record.mjs` | `tools/video-overview/record.mjs` | один раз; правки только при технических изменениях |
| `synth-eleven.py`, `measure-segments.py`, `build-track.py` | `tools/video-overview/` | один раз |
| `scene-actions.json`, `segments.json`, mp3, timestamps, видео, итоговый ролик | `/tmp/KS-XXXX/`, `/tmp/voiceover/KS-XXXX/` | НЕ коммитим (артефакты записи) |
| Сценарий, ADR | `docs/architecture/video-overview-series.md`, `docs/adr/123-...` | коммитим |

## 3. Альтернативы и обоснование

### 3.1 Посегментный рендер (отклонено)

Координатор предложил вариант: каждый сегмент — отдельная мини-запись + отдельный mp3, склейка через `ffmpeg concat`. Технически проще, но:
- **Непрерывная WebSocket-партия.** Шаги 5–10 в A2 — одна live-игра. Разорвать их — каждый сегмент начнётся с нового `/game/:id`, новой расстановки. Технически сложно и неестественно в кадре.
- **Состояние UI.** Шаги 1–4 на `/play` — один пользовательский поток (выбрал контроль → настроил фильтр → нажал «Играть»). Дробление = повтор предыдущих кликов в каждой мини-записи.
- **Двухконтекстная съёмка.** A и B — две параллельные записи. Посегментный подход потребовал бы ручной синхронизации на стыках.
- **Артефакты на стыках.** ffmpeg concat может уронить keyframes, появится видимый jitter.

Конвейер v2 даёт ту же атомарность правок (правка одного сегмента → автоматическая ре-синхронизация), без минусов посегментного.

### 3.2 Forced alignment вместо ElevenLabs (резерв)

Если пользователь решит НЕ использовать ElevenLabs программно (например, продолжит брать готовые mp3 из Artlist), посимвольные тайминги получаются через forced-alignment (`aeneas`, `whisper-timestamped`). Это резервный путь — точность ниже (типичная погрешность 50–150 мс против < 20 мс у ElevenLabs API), но контракт `scene-actions.json` остаётся прежним.

Рекомендация (см. KS-4062 комментарии): использовать ElevenLabs программно. У пользователя ключ уже есть.

### 3.3 Сохранить текущий «видео первично» подход (отклонено)

Просто документировать процесс ручной подгонки. Каждая правка озвучки = N часов QA. Не масштабируется на серию из 20+ обзоров.

## 4. План реализации (заводится отдельными задачами)

1. **devops-задача:** хранить `ELEVENLABS_API_KEY` как env-переменную webhook-контейнера. Положить `synth-eleven.py` и `measure-segments.py` в `tools/video-overview/`. Документировать в README репозитория.
2. **QA-задача:** переписать `record.mjs` под durMs-driven + планирование по якорям. Перенести в `tools/video-overview/record.mjs`. Адаптировать `build-track.py` к новому формату placements (изменения минимальные).
3. **архитектор-задача:** для каждого тикета серии писать `scene-actions.json` рядом со сценарием. По A2 готовый образец — `/tmp/KS-4062/scene-actions.json`.
4. **Обновление `video-overview-series.md`:** переписать раздел 1.6 «Сборка аудиодорожки» под новый поток (этот ADR + ссылка).

После выполнения шагов 1–3 повторное производство любого тикета серии укладывается в один запуск `make video KEY=KS-XXXX` без ручной подгонки.

## 5. Принимаемое решение

Принят подход «аудио первично + слова-якоря» по разделу 2. Описание шагов конвейера и формат `scene-actions.json` фиксируются в этом ADR как обязательные для всей серии видеообзоров.

Альтернатива «посегментный рендер» отклонена.

Альтернатива «forced alignment вместо ElevenLabs API» сохраняется как резерв для случаев, когда озвучка приходит готовыми mp3 от стороннего поставщика.
