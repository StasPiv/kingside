# ADR-057: Разделение `/precision` — тренировка отдельно от статистики и истории

**Дата:** 2026-05-11
**Автор:** architect
**Связанная задача:** KS-2742
**Связанные ADR:** ADR-048 (Precision Training section), ADR-055 (раздельная статистика — инфра), ADR-056 (метрики precision-режима, текущая модель данных)
**Связанные задачи:** KS-2714 (метрики precision), KS-2719 (PrecisionAttemptPage), KS-2724 (история попыток), KS-2740, KS-2728 (тренды/breakdowns)

---

## 1. Контекст и проблема

ADR-056 определил три уровня метрик precision-режима (А — top-cards, Б — detail-page, В — тренд + breakdowns). Эти блоки последовательно реализовали в KS-2714/2719/2724/2728/2740 и собрали в одну страницу `/precision`.

В итоге на `/precision` сейчас в одной вертикальной колонке:

1. Заголовок и intro.
2. Toolbar (`← Все пазлы`, `Генерация из PGN`).
3. Фильтр «Все / Мои».
4. Top-блок из 4 карточек (точность / удержано-упущено / WDL-leak / до первой ошибки).
5. Toggle «Скрыть удержанные».
6. История попыток (`PrecisionAttemptsList`) — карточки с превью досок.
7. Тренд точности (`PrecisionTrendsChart`) — неделя/месяц.
8. Разбивки по фазе игры и темам (`PrecisionBreakdowns`).
9. **Сетка позиций для тренировки** — то, ради чего пользователь сюда заходит.
10. Floating toast.

На 1280×800 первый экран показывает заголовок + toolbar + статистику; на 1440×900 — то же плюс верх «Истории попыток». Сетка позиций видна только после 1–2 экранов скролла.

Жалоба пользователя (Telegram, 2026-05-11):

> Статистика в разделе точности должна быть на отдельных страницах, иначе она занимает все место и не видны сами пазлы для тренировки. UX продумать архитектору, функционал у нас есть, но пока не юзабельный.

Функционал реализован полностью, не хватает информационной архитектуры: главный экран раздела должен быть **про действие** (выбрать позицию и начать тренировку), а не про метрики.

## 2. Информационная архитектура: маршруты vs табы

Кандидаты:

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Табы внутри `/precision`** (state в `?tab=training\|progress\|history`) | Один файл, общий header без перезагрузки контекста, мгновенное переключение | Раздувание `PrecisionPage` (уже 920 строк), сложнее раскалывать на code-split, deep-link через `?tab=` менее чист |
| **B. Отдельные роуты `/precision`, `/precision/stats`, `/precision/history` + общий sub-nav** | Code-splitting естественный, каждая страница тестируется отдельно, deep-link чистый | Между переключениями полный mount каждой страницы (новые API-запросы) |
| **C. Гибрид: главная `/precision` = тренировка; `/precision/stats` и `/precision/history` — отдельные роуты, sub-nav сверху** | То же что B, но решение явно сфокусировано на главной | — |

### 2.1 Выбираем B (= C). Обоснование:

1. **Размер исходника.** `PrecisionPage.tsx` сейчас 920 строк (тяжёлая страница с десятком useState/useCallback). Сваливать в неё ещё «Прогресс»+«История» через табы — раздувание до 1500+ строк. Три страницы по 200–400 строк лучше поддерживаются и тестируются.
2. **Code-splitting.** `PrecisionTrendsChart` и `PrecisionBreakdowns` тянут отдельные API (`/precision/trends/me`, `/precision/breakdowns/me`). На главной они не нужны — пусть грузятся только при заходе на `/precision/stats`. Это и есть «не видны → не запрашиваем».
3. **Deep-linking.** Ссылка `/precision/stats` понятнее чем `/precision?tab=progress`, и она же согласована с существующим `/precision/attempts/:id`.
4. **Согласованность с проектом.** В `/lessons` используются табы (`?tab=mine`), но lessons — это смежные списки одного типа сущности (системные/мои/мои-активные). У precision три **разных** типа активности (тренировка / агрегаты / журнал). Это другой кейс — ближе к `/puzzles` vs `/puzzles/stats` vs `/puzzles/mistakes`, где уже выбраны отдельные роуты.
5. **Sub-nav как табы.** Визуально UX тот же что у табов — горизонтальный nav сверху с активным состоянием по `useLocation`. Пользователь не различает «таб» и «sub-route» — он видит три ссылки.

### 2.2 Карта маршрутов

| Маршрут | Назначение | Состояние |
|---|---|---|
| `/precision` | Главная: тренировка. Compact top-bar + сетка позиций. | Новый (рефакторинг текущей) |
| `/precision/stats` | Полная статистика: 4 top-карточки, тренд, разбивки. | Новый |
| `/precision/history` | История попыток с фильтрами и пагинацией. | Новый |
| `/precision/attempts/:id` | Разбор конкретной попытки (KS-2719). | Без изменений |

### 2.3 Что НЕ меняем

- Backend — ничего. Все endpoint'ы из ADR-056 (`/precision/stats/me`, `/precision/attempts/me`, `/precision/trends/me`, `/precision/breakdowns/me`, `/precision/attempts/:id`) остаются как есть. Перемещение блоков — фронтовый рефакторинг.
- `PrecisionAttemptPage` — без изменений.
- `precision-tabs` (фильтр «Все / Мои»), `hideRetained` toggle, генератор из PGN, тулбар-кнопки — остаются на главной `/precision`.
- Sidebar: один пункт «Тренировка точности» (🎯, ведёт на `/precision`). См. §6.

### 3.2 Compact top-bar (1 строка)

Назначение — не «показать статистику» (для этого есть отдельная страница), а «дать сигнал что прогресс есть + предложить углубиться».

Содержимое:
- **2 метрики** — `avgAccuracyPercent` и `preservedCount/totalAttempts`. Источник тот же `GET /precision/stats/me`. Лёгкий запрос, его уже делает текущий код.
- **Ссылка** «Полная статистика →» ведёт на `/precision/stats`.

Высота строки — ~32–40px (одна строка text + ссылка). На 1280×800 это оставляет ≥520px под сетку до fold'а — достаточно для 1 ряда карточек (3–4 шт.) видимых сразу.

Состояния:
- `user=null` (гость) — bar не рендерится. Сразу сетка.
- `stats=null` или `totalAttempts=0` — bar показывает CTA: «Сыграй первую попытку чтобы видеть свою точность» + ссылка «Все позиции для тренировки →» (anchor на сетку, безоп для деградации). Опционально — `[Случайная позиция]` кнопка для быстрого старта (см. §3.4).
- `loading=true` — пустая высота строки (skeleton не нужен — слишком короткая, мигание раздражает больше).

### 3.3 Sub-nav (3 ссылки)

Компонент `<PrecisionSubNav />` — общий для трёх страниц раздела.

- Рендерится сразу под `<h1>` (или под intro), до toolbar'а.
- Активный пункт определяется по `useLocation().pathname`:
  - `/precision` → «Тренировка»
  - `/precision/stats` → «Прогресс»
  - `/precision/history` → «История»
- `role="tablist"` / `role="tab"`, `aria-selected`. Под капотом — `<Link>` (deep-linkable, middle-click работает).
- Гостям пункты «Прогресс» и «История» можно показывать, но они должны давать понятный empty (или редирект на `/login`). Решаем: для гостей пункты **скрыты** — на этих страницах endpoint вернёт 401, нет смысла туда вести (тот же подход что у `/lessons/my-active`).

### 3.4 Entry-points «Продолжить» / «Случайная позиция»

Задача требования (§2) упоминает их. Анализ:

- **«Продолжить последнюю попытку»** — `PrecisionAttemptPage` это **разбор**, а не продолжение игры. Семантически «продолжить» в precision-режиме = открыть последнюю попытку в режиме разбора. Это уже доступно из `/precision/history` (карточка → «Разбор»). Дублировать на главной — нет ценности.
- **«Случайная позиция»** — кнопка-action рядом с тулбаром. Реализуется через `GET /puzzles/browse?source=generated&limit=1&randomize=1` (если есть randomize-параметр) или клиентским выбором случайной из уже загруженной сетки. Это полезное действие, но требует backend-поддержки. **Выносим в отдельный тикет за рамками этого ADR** (F-G ниже, опционально).

В рамках MVP этого ADR на главной хватает: сетка + compact top-bar + тулбар + фильтры. Если у юзера 0 attempts — добавляем CTA «Сыграй первую попытку» (см. §3.2).

| Блок | Куда |

| 4-карточный top-блок (`precision-stats`) | `/precision/stats` (без изменений отображения) |
| `PrecisionAttemptsList` | `/precision/history` |
| `PrecisionTrendsChart` | `/precision/stats` (под top-карточками) |

Что остаётся:
- Заголовок + intro.
- Sub-nav (новое).
- Compact top-bar (новое, см. §3.2).
- Toolbar (`← Все пазлы`, `Генерация из PGN`).

## 6. Sidebar / навигация

### 6.1 Sidebar — без подпунктов

В `Sidebar.tsx` остаётся один пункт «Тренировка точности» (🎯 → `/precision`).

Обоснование:
- Подразделы добавлять в sidebar — раздувание дерева. У `/puzzles`, `/drills`, `/lessons` в sidebar тоже по одной кнопке, sub-навигация — внутри страницы.
- Sub-nav на странице делает то же что подпункты sidebar, но без визуального шума в общем меню.
- Пользователь, попавший на `/precision`, моментально видит «Тренировка / Прогресс / История» — sub-nav в шапке самой страницы это первый видимый ряд после `<h1>`.

### 6.2 MobileBottomBar

`MobileBottomBar` — без изменений. Кнопка `/precision` остаётся как top-уровень. Sub-nav внутри страницы виден после клика по кнопке.

### 6.3 URL-канон

- Все ссылки внутри проекта на `/precision` (главная) — без изменений.
- Существующие алиасы:
  - `/puzzles/play-vs-engine` → `/precision` (KS-2538 / ADR-048) — остаётся.
- Новые ссылки на `/precision/stats` и `/precision/history` — добавляются по мере необходимости (компонент `<PrecisionSubNav />` сам ведёт). Внешних entry-point'ов на них пока нет.

## 7. Mobile (≤640px)

### 7.1 Sub-nav

Горизонтальная полоска из трёх кнопок-табов. Варианты:
- **Full-width 3-кнопки** (33% каждая) — простой и читаемый. Текст укорачиваем до «Тренировка / Прогресс / История» (умещается на iPhone SE 320px? Проверить — «Тренировка» 9 символов, влезает). Если нет — допустимо «Учить / Прогресс / Журнал».
- **Прокручиваемая полоска** (scroll-snap) — для расширяемости (если добавится 4-й пункт). На MVP избыточно.

Выбираем full-width 3 кнопки. CSS — `display: flex; flex: 1` для каждой ссылки.

### 7.2 Compact top-bar на главной (mobile)

- В одну строку 2 метрики + ссылка не помещаются — переносим в 2 строки или скрываем «Полная статистика →» (всё равно есть sub-nav «Прогресс» сверху).
- Решение: на mobile compact top-bar = одна строка «Точность 82% · Удержано 3/7». Ссылка «Полная статистика →» убирается (дубль sub-nav). Высота ~28px.

### 7.3 `/precision/stats` mobile

- 4 карточки top-блока: на 2 колонки 2×2 (вместо 1×4 на desktop). Это уже работает в текущем `precision-stats` CSS (KS-2719 F2 предусматривает grid-template-columns с media query).
- Тренд: график sparkline во всю ширину, легенда Неделя/Месяц над ним.
- Breakdowns: списки в одну колонку (sequentially), не side-by-side.

### 7.4 `/precision/history` mobile

- Карточки попыток уже layout'нуты вертикально (доска сверху, текст снизу, кнопка «Разбор» внизу). Должно работать без правок CSS.
- Фильтры «Все / Удержано / Упущено» — full-width 3-кнопки, как sub-nav.

### 7.5 `/precision` mobile (главная, сетка карточек)

- Сетка карточек: 2 колонки на ≥360px, 1 колонка на <360px. Уже работает.
- Фильтр «Все / Мои» (`precision-tabs`) — full-width 2 кнопки.

## 8. Декомпозиция тикетов

Все — frontend / layout. Backend не трогаем (см. §2.3).
