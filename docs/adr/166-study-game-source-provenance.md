# ADR-166: Источник партий для game-шага персонального урока Study

**Дата:** 2026-07-17
**Статус:** Предложено
**Задача:** (консультация координатора, уточнение ADR-162 §3.1/§4)
**Связанные ADR:** 162 (study-v2-personal-lesson), 072 (game-шаг урока)

---

## 1. Контекст и проблема

Требование пользователя: партии для разбора в персональном уроке должны сами
импортироваться из привязанных аккаунтов (`lichessUsername`/`chesscomUsername`);
если реальных партий нет — game-шаг пропускать; не подсовывать мусор.

Факты кода (2026-07-17):
- `BaselineMaterialSource.extract` (`apps/api/src/study/material/baseline-material.source.ts`)
  берёт последние `PgnImportGame` по `import.userId` **без фильтра происхождения** —
  в разбор попадают ручные PGN, чужие/учебные партии, любой загруженный файл.
- Происхождение импорта нигде не хранится явно. `PgnImport` имеет только `fileName`.
  Авто-импорт помечен именем `study-auto (<provider>).pgn`
  (`study-tracking.scheduler.ts`), ручная загрузка и `import-external` — произвольным.
  Различение по `fileName` — хрупкое (переименование, коллизии).
- Авто-импорт (`autoImportDay`) тянет **только вчерашние** партии → у только что
  привязавшего аккаунт пользователя материала нет до следующей ночи.
- `buildNotes` не умеет атрибутировать цвет/результат — нет привязки партии к
  игроку (нет username-мэтча).

## 2. Решение

### 2.1 Явное поле происхождения `PgnImport.origin`

Добавить колонку `origin String @default("manual")` в `PgnImport`. Значения:
`manual` | `external_lichess` | `external_chesscom` | `auto_lichess` | `auto_chesscom`.
Проставляется в точке импорта (`WorkshopService.importPgn` получает параметр
`origin`; контроллер `import-external` и крон трекинга передают своё значение).

Бэкфилл существующих строк одноразовой миграцией: `fileName` начинается с
`study-auto (lichess)` → `auto_lichess`, `... (chesscom)` → `auto_chesscom`,
остальное → `manual`.

Происхождение — источник истины о провенансе. Парсить `[Site]`/`[Link]` из PGN на
каждом чтении не нужно (дороже и не покрывает старые импорты без тегов).

### 2.2 Фильтр материала game-шага

`gameFragments` (и агрегаты `notes`) собираются **только** из партий с
`origin ∈ {auto_lichess, auto_chesscom, external_lichess, external_chesscom}`.
`manual` в game-шаг и в notes не попадает.

Дополнительно — мэтч по имени игрока: из online-партий берутся те, где
`white` или `black` равен привязанному username (регистронезависимо). Это:
1. выбирает **собственные** партии пользователя, а не соперника/чужие;
2. даёт корректную атрибуцию цвета и результата в `notes`
   (закрывает текущий пробел `buildNotes`).

### 2.3 Глубина импорта: разовый бэкфилл при привязке

Ежесуточный инкремент (вчера) остаётся. Дополнительно — **разовый бэкфилл** при
первой доступности username (привязка аккаунта или первый сбор урока с пустым
online-материалом): дотянуть последние партии за окно **30 дней ИЛИ последние 20
партий на провайдер, что меньше**. Окно ограничено ради rate-limit'ов внешних API.
Помечается тем же `origin=auto_*`, дедуп существующий (Link/Site) не даёт дублей
с ночным инкрементом.

### 2.4 Поведение при отсутствии партий

Нет квалифицированных партий → `gameFragments = []` → `StudyLessonBuilder`
**пропускает game-шаг** целиком. Урок собирается в fallback (тема + пазлы +
quiz/drill), как ADR-162 §3.2. Плейсхолдер/ручной PGN в game-шаг не подставляется
никогда. Онбординг-баннер «нет материала» (ADR-162 §3.2) остаётся.

## 3. Влияние на ADR-162

Уточняет (не отменяет):
- §3.1 — добавляется поле `origin` и разовый бэкфилл при привязке (было: только вчера);
- §4 — `BaselineMaterialSource` фильтрует по `origin` + username-мэтч, game-шаг
  скипается при пустом результате (было: последние 2 партии без фильтра).

## 4. Отклонённые альтернативы

- **Различать происхождение по `fileName`** — хрупко (переименование, коллизии,
  старые импорты); явная колонка надёжнее и индексируется.
- **Парсить `[Site]`/`[Link]` из PGN при каждом чтении** — дороже, не покрывает
  импорты без тегов; провенанс должен фиксироваться при записи.
- **Пускать `manual` PGN в game-шаг** — прямо нарушает требование «не подсовывать
  мусор»: ручной файл может быть учебной/чужой партией.
- **Полный реимпорт истории аккаунта** — rate-limit и нагрузка; окно 30 дней/20
  партий даёт материал сразу без риска (симметрично отказу ADR-162 §7).

## 5. Декомпозиция (backend, 1 задача)

Миграция `PgnImport.origin` + бэкфилл; параметр `origin` в `importPgn` и всех
вызовах (workshop-контроллер, крон трекинга); фильтр `origin` + username-мэтч в
`BaselineMaterialSource`; корректная атрибуция в `buildNotes`; разовый бэкфилл при
привязке/пустом материале (окно 30д/20 партий); скип game-шага при пустом
`gameFragments`. Метки: `prisma`, `game`.
