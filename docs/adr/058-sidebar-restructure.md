## 1. Контекст

Запрос пользователя (Telegram, 2026-05-11): «надо сделать ревизию
разделов и логику отображения пунктов меню в левой панели на десктопе
и в нижней панели на мобильном». На скриншоте `/tmp/telegram/
326129694_0.jpg` видна вертикальная колонка с 11+ иконками подряд:
🏠 ♟ 🏆 🧩 ⚡ 🧠 🎯 🎓 🔬 📚 📺, ниже divider и ещё 📋 ✨ 👥 ⚙ (+ 🛡
для админа, 📝 кнопка feedback'а в футере). Иерархии нет, всё в
один уровень.

Параллельно по KS-2793 решено: пункт «Уроки» переименовывается в
«Обучение», каталог Studies становится табом внутри `/lessons`. То есть
в этом ADR — не появляется нового пункта Studies; пункт «Обучение»
заменяет «Уроки».

Цель документа: предложить структуру меню (топ-уровневые ≤7 пунктов на
desktop + 3+1 на mobile), сгруппировав вторичные пункты, и составить
список frontend-задач под реализацию.

### 2.2 Mobile Bottom Bar (`apps/web/src/components/MobileBottomBar.tsx`)

Логика (KS-2373): 3 кнопки top-3 + кнопка «Ещё». Top-3 динамически
подтягивается из `GET /user/nav-stats/top?limit=3` (backend учитывает
переходы пользователя). Default до получения ответа: `['play',
'tournaments', 'workshop']`.

Whitelist (`useNavStats.ts` → `NAV_ROUTES`): play, tournaments,
workshop, lessons, drills, broadcasts, archive, profile, puzzles,
precision (10 routes). «Ещё» открывает выпадающий список из остатков
whitelist'а + features, friends, feedback, settings, admin.

Состояние: top-3 — частотные сценарии (полезно), но whitelist
не покрывает все категории (например, у активного «тактика» в top-3
могут оказаться puzzles+drills+precision — фактически три тренировочные
кнопки, и потеряется быстрый доступ к Play/Workshop). Внутри «Ещё»
нет группировки — плоский список 6–8 ссылок.

### 2.3 Оценка частоты использования (без аналитики, экспертная)

Точной аналитики переходов на руках у архитектора нет — `nav-stats`
есть у backend (`POST /user/nav-stats/increment`), но дамп её в ADR не
выгружен. Ниже — экспертная оценка приоритета сценариев на основе
архитектуры продукта:

| Категория | Сценарии | Частота (экспертно) |
|-----------|---------|---------------------|
| Play | играть быстрые/блиц/классика; турниры | **очень высокая** (ежедневная) |
| Train | задачи, rush, drills, precision | **высокая** (несколько раз/нед., но эпизодически) |
| Learn | уроки, курсы | **средняя** (для новичков — высокая, для опытных — низкая) |
| Analyze | workshop, архив | **средняя** (после каждой партии у мотивированных) |
| Watch | трансляции | **низкая для большинства**, **высокая для турнирной аудитории во время событий** |
| Social | друзья, профиль, чат | **средняя** |
| Utility | настройки, feedback, features, admin | **редко** (1 раз за сессию или реже) |

Эта оценка — гипотеза; перед реализацией предлагаю экспортнуть
агрегированный `nav-stats` (есть на backend, ADR-в-курсе) и подкрепить
расстановку реальными числами (см. §6.1 в декомпозиции).

## 3. Информационная архитектура — группировка

Из аудита выделяются 4 «обучающие/тренировочные» пункта подряд (🧩 🧩
⚡ 🧠 🎯) и 2 «аналитических» (🔬 📚). Эти группы — кандидаты на
сворачивание.

### 3.1 Концептуальные группы

| Группа | Что входит сейчас | i18n-ключ группы |
|--------|---------------------|---------|
| **Играть** (Play) | Играть, Турниры | `nav.play` (расширить) |
| **Тренировка** (Train) | Задачи, Puzzle Rush, Тренажёры, Точность | `nav.train` (новый) |
| **Обучение** (Learn) | Уроки (+ Студии-таб по KS-2793) | `nav.learn` (переименовать `nav.lessons`) |
| **Анализ** (Analyze) | Лаборатория, Архив | `nav.analyze` (новый) |
| **Трансляции** (Watch) | TV | `nav.tv` |
| **Социальное / Утилитарное** | Друзья, Настройки, Feedback, Features, Admin | в footer / drawer |

Если каждая группа на desktop — один топ-уровневый пункт, то получаем
**5 «контентных» + 1 ссылка `🏠 Главная`** = **6 пунктов**. Это укладывается
в лимит «5–7» из ТЗ.

### 3.2 Что делать с «утилитарным»

В sidebar выносится фиксированный «footer-блок» (как сейчас) с
4 иконками:

| Иконка | Куда |
|--------|------|
| 👤 / 🟢 | Профиль / статус пользователя (ссылка `/profile`) |
| ⚙ | Настройки (`/settings`) |
| 📝 | Feedback (модалка, как сейчас) |
| 🛡 | Admin (только админ) |

Друзья (👥) и Features (✨) — переезжают в «Профиль» как сабменю
(`/profile/friends`, `/profile/features` или как табы). Сценариев заходить
в «Друзей» или «Возможности» из любого места приложения мало — это
профильный workflow.

Альтернатива: оставить «Друзья» как самостоятельный пункт sidebar,
если будет social-эпик в roadmap'е. Решает координатор. По умолчанию
в этом ADR — спрятать.

### 3.3 Submenu vs single-page vs drawer

Три варианта раскрытия группы при клике на топ-пункт:

**A. Single-page** (рекомендуемый для большинства): клик на «Тренировка»
открывает `/train` — лобби, где карточками выложены 4 подраздела с
описаниями. Это естественно для новичка («что такое drills?» — увидит
карточку с описанием). Используется уже для Lessons (DiscoverCoursesPage)
и Archive.

**B. Submenu (раскрывающийся ряд иконок)**: при наведении/клике
открывается ряд из 4 иконок прямо в sidebar. Минусы: занимает место,
плохо работает на узких экранах, нет места под подписи. Уместно
только для desktop, и только если у группы 2–3 пункта.

**C. Drawer (выезжающая панель)**: вторичный sidebar справа от
основного, скрытый по умолчанию. На наш текущий лэйаут (sidebar 64px
шириной + контент) — много усилий, мало пользы.

Решение: **single-page лобби** для каждой группы (`/train`, `/analyze`).
Submenu — только как hover-фичу (tooltip с тремя ссылками) — это
nice-to-have, не блокирует MVP.

### 3.4 Mobile-стратегия

Mobile bottom bar физически вмещает **4–5 кнопок**. Сейчас фиксированно
3+1 (3 top + «Ещё»). Предлагается перейти к **фиксированному набору 5 кнопок**:

```
[♟ Играть] [🎓 Обучение] [🧠 Тренировка] [🔬 Анализ] [⋯ Ещё]
```

Это покрывает 4 контентные группы + drawer для остального. Динамическая
«частота» (KS-2373) теряется, но взамен:

- Пользователь видит **постоянный набор** — обучается ярлыкам.
- На mobile play-сессия не ломает порядок: «Игра» всегда первая.
- Метки и иконки одинаковые между desktop и mobile — узнаваемость.

Альтернатива: оставить KS-2373 динамический подход, но **в whitelist
ввести группы** (`train`, `analyze`, `learn`, `play`), а не отдельные
маршруты. nav-stats agg по группе, не по route.

Решение: **зафиксировать 4+1**, отказаться от динамики на mobile.
Аргумент: KS-2373 ввели до того, как пунктов разрослось — сейчас
полезнее предсказуемость. KS-2373 не теряем — переиспользуем
backend, но как «эвристика порядка» внутри `Профиль → Активность» или
для UTM-аналитики.

«Ещё» (drawer) на mobile группирует: Трансляции, Турниры, Друзья,
Профиль, Настройки, Feedback, Features, Admin.

## 4. Предложение новой структуры — Desktop

### 4.1 Топ-уровневые пункты (sidebar)

```
┌──── sidebar (≈64px) ────┐
│                          │
│  🏠   Главная            │  nav.home → /lobby
│  ♟    Играть             │  nav.play → /play (Турниры — таб/раздел внутри)
│  🧠   Тренировка         │  nav.train → /train (Задачи, Rush, Drills, Precision)
│  🎓   Обучение           │  nav.learn → /lessons (+ таб Студии, KS-2793)
│  🔬   Анализ             │  nav.analyze → /workshop (+ таб Архив)
│  📺   Трансляции         │  nav.tv → /broadcasts
│                          │
│  ──── divider ────       │
│                          │
│  👤   Профиль            │  /profile (Друзья, Features — табы)
│  ⚙   Настройки          │  /settings
│  📝   Feedback (модал)   │
│  🛡   Админка            │  adminOnly
└──────────────────────────┘
```

**6 контентных** пунктов сверху + **3–4 утилитарных** в нижнем блоке.
Сейчас на скриншоте — 11 контентных подряд. Сокращение в ~2 раза.

### 4.2 Что происходит при клике

| Топ-пункт | Behaviour |
|-----------|-----------|
| 🏠 Главная | `/lobby` — единственная страница |
| ♟ Играть | `/play` — основной экран; **таб «Турниры»** внутри (или подменю tooltip) |
| 🧠 Тренировка | `/train` — лобби с 4 карточками: Задачи / Rush / Drills / Точность. Каждая карточка ведёт на свой существующий маршрут |
| 🎓 Обучение | `/lessons` (можно сделать редирект `/learn` → `/lessons` или оставить URL как есть; пересмотрено в KS-2793 §7.7) — внутри табы «Курсы / Студии / Мои» |
| 🔬 Анализ | `/workshop` — табы «Лаборатория / Архив / Партии по позиции» |
| 📺 Трансляции | `/broadcasts` — без изменений |

Если flag-flag выключает подраздел (например, `drillsEnabled=false`),
карточка в лобби `/train` скрывается, либо рендерится в «coming soon»
состоянии (зависит от продуктового решения).

### 4.3 Поведение «активная подсветка»

Подсветка топ-пункта — если pathname **попадает в любой из
вложенных маршрутов**, не только в точный URL пункта. То есть:

- `/puzzles*`, `/puzzle-rush*`, `/drills*`, `/precision*` → подсветка `🧠 Тренировка`.
- `/workshop*`, `/analysis*`, `/archive*` → подсветка `🔬 Анализ`.
- `/lessons*` (включая будущие `/lessons?tab=studies` и
  `/analysis/study/<chapter>` — последнее обсуждается в KS-2793) →
  `🎓 Обучение`.

Реализация — расширить `NavItem.match` массивом всех вложенных
префиксов, как уже сделано для `workshop` (`['/workshop','/analysis']`).

## 5. Предложение новой структуры — Mobile

### 5.1 Bottom bar (фиксированный, 5 кнопок)

```
┌──────────────────────────────────────────────────────────┐
│                                                           │
│                 содержимое страницы                       │
│                                                           │
├──────────────────────────────────────────────────────────┤
│  ♟       🧠         🎓          🔬         ⋯             │
│ Играть Тренировка Обучение    Анализ      Ещё            │
└──────────────────────────────────────────────────────────┘
```

5 кнопок, фиксированный порядок, mirror desktop (Play /
Train / Learn / Analyze / More). Главная (`/lobby`) убирается из bar'а
— домик не используется как «вернуться» (есть Kingside-лого в шапке).
Трансляции (`/broadcasts`) переезжают в drawer «Ещё», так как для
большинства это редкая активность.

```
│   👥 Друзья            /profile/friends  │
│   🏆 Турниры           /tournaments      │
│                                          │
│ ▸ Аккаунт                                │
│   👤 Профиль           /profile          │
│   ⚙ Настройки         /settings         │
│                                          │
│ ▸ Помощь                                 │
│   ✨ Возможности       /features         │
│   📝 Обратная связь    (модалка)         │
│                                          │
│ ▸ Админ (виден только админу)            │
│   🛡 Флаги             /admin            │
└──────────────────────────────────────────┘
```

3–4 группы с заголовками. Это решает «плоский список 8 ссылок»
текущего more-menu.

### 5.3 Что происходит с KS-2373

KS-2373 (динамические top-3 по nav-stats) — снимается с mobile bar'а
ради предсказуемости. Backend-эндпоинты `POST /user/nav-stats/
increment` и `GET /user/nav-stats/top` **остаются** — могут
использоваться:

- в `/lobby` («Продолжить там, где вы остановились» — карточка с
  последним посещённым разделом);
- в drawer «Ещё» (порядок пунктов внутри подгрупп);
- в маркетинговой аналитике.

Это рекомендация — финальное решение по KS-2373 (оставить / выключить
/ переиспользовать) согласуется с product-владельцем.

## 8. Риски

1. **Регрессия в активной подсветке** (KS-2790 уже чинили похожее).
   Митигация: KS-2791.10 явно требует тестов; берём паттерн из
   текущего `match`-массива `workshop`.
2. **Старые ссылки в i18n** на `/puzzles` и т. п. — продолжают работать
   (маршруты не удаляются, удаляются только пункты sidebar). Закладок и
   обмена ссылками не ломаем.
3. **«Где же Drills?»** — пользователь, привыкший к старому sidebar'у,
   не найдёт раздел. Митигация: KS-2791.14 changelog + при первом
   рендере новой структуры в течение N дней — onboarding-tooltip
   («Тренажёры теперь в разделе Тренировка»).
4. **Лимит feature-flag gating: «все 4 train подраздела выключены»**.
   В текущем sidebar — пункт просто скрыт. В новом — если все 4
   выключены, скрываем `Train` целиком; если выключены частично —
   `TrainLobbyPage` показывает только включённые карточки. Логика
   gating переезжает с пунктов на карточки лобби.
5. **KS-2793 ещё не реализован**: KS-2791.3 (таб «Студии» в Lessons)
   зависит от KS-2793 MVP. Если KS-2793 идёт позже — выполняем
   KS-2791 без §6.2/2791.3 и без переименования `nav.lessons` →
   `nav.learn` (оставляем «Уроки», добавим переименование как
   часть KS-2793).

## 9. Открытые вопросы (на согласование)

1. **Переименование `nav.lessons` → `nav.learn`** — делать в этой
   задаче или в KS-2793? Рекомендация: в KS-2793, где появляется
   повод (таб «Студии»).
2. **«Турниры» — отдельный пункт sidebar или под `Играть`?**
   Аргумент в пользу отдельного пункта: турниры активно используются,
   `/tournaments` — самостоятельный маршрут с расписанием.
   Аргумент в пользу слияния: концептуально это «играть в формате
   турнира». Рекомендация: оставить отдельным пунктом sidebar **внутри
   группы Играть** — два пункта подряд (`♟ Играть`, `🏆 Турниры`) — это
   приемлемо, и пользователь активно ищет «Турниры» именно как
   самостоятельный раздел. То есть **топ-уровневых станет 7, не 6**.
   Решение оставить за координатором.
3. **`/lobby` как пункт sidebar — нужен ли?** Логотип Kingside в
   шапке и так ведёт на главную. Можно убрать `🏠` пункт целиком и
   сократить до 5–6.
4. **«Друзья» — куда?** В `/profile`-таб (как предложено) или
   оставить отдельным пунктом? Если в roadmap'е есть «social-эпик»
   (чат, leaderboards) — отдельный пункт оправдан.
5. **Отключить KS-2373 (динамический top-3 mobile)?** Или
   переиспользовать (см. §5.3). Решение продукта.
6. **«Главная (`/lobby`) vs стартовая для залогиненного пользователя»** —
   после редизайна может появиться argument сделать стартовой страницей
   `/play` (играть в один клик), а `/lobby` оставить как дашборд для
   тех, кто хочет «осмотреться». В рамках этого ADR — не решается,
   но стоит зафиксировать.
