# ADR-096. UX постоянного анализа Maia на странице анализа

Статус: предложен (KS-3582).
Дата: 2026-06-02.
Связано: KS-3577 (клиентская Maia), KS-3579 (кнопка «Получить рейтинг позиции»), KS-3580 (fallback-список), KS-3581 (стилизация блока), ADR-073 (mobile bottom-sheet анализа).

## 1. Контекст

На странице анализа сегодня:

- В `engine-panel` (collapsible, `pages/analysis/AnalysisSidebar.tsx` ≈ строки 280-414 desktop, 580-624 mobile) рендерятся линии Stockfish: top-N (`ec.multiPv` 1..10) с `eval` (CP/mate) и PV (SAN).
- Над линиями — селектор MultiPV (`engine-multipv-controls`, кнопки `−`/`+`), `engine-settings-btn` (выбор source: wasm/external + depth/threads), `analysis-toggle-btn` (Start/Stop).
- Под линиями — `PositionMaiaRatingButton` (KS-3579/3580): точечный сценарий «нажми → подожди → увидь рейтинг, на котором Maia предложит тот же ход что Stockfish, либо top-3 от 2400».
- Maia на клиенте уже готова: `predictMoves(fen, eloSelf, eloOpp)` и `MaiaWorkerEngine.predictMovesBatch(fen, [elos], [elos])` (`apps/web/src/lib/maia/`). Один прогон в воркере ≈ 1 с на батч из 14 рейтингов, для одного ELO быстрее.

Пользователь хочет: видеть **постоянный** анализ Maia (как сейчас линии Stockfish — топ-N с вероятностями), под выбираемый ELO. Это становится **полноценным режимом анализа**, а не точечной кнопкой.

## 2. Цели и нон-цели

### Цели

1. Maia top-N для текущей позиции на доске **обновляется автоматически** при каждой смене FEN (по аналогии со Stockfish).
2. Пользователь выбирает целевой ELO одним контролом (slider или select 1100..2400 шаг 100).
3. Выбранный ELO **запоминается между сессиями** (localStorage).
4. UX не «жрёт» мобильный экран — обе модели должны помещаться или сворачиваться разумно.
5. Решение про судьбу кнопки KS-3579 (включить в новый блок / удалить / оставить как shortcut).

### Нон-цели

- Не делаем UI (реализацию). Эта задача — только дизайн-решение.
- Не переписываем Stockfish-блок.
- Не добавляем server-side Maia.
- Не оцениваем «силу» каждого хода относительно best (это потенциально интересно, но за рамками: упомянуто в §9 как future).
- Multi-Maia (одновременно несколько ELO) — за рамками (только один выбранный ELO).

## 3. Решение (краткое)

Принимаем **гибрид C** (предлагается как третий вариант поверх A/B из тикета):

- **Maia рендерится как отдельная подсекция ВНУТРИ существующей `engine-panel`**, под Stockfish-блоком, с разделителем.
- В шапке Maia-подсекции — селектор ELO (compact: select+стрелки или короткий slider) и `Top-N` контрол (3/5, по умолчанию 5).
- Maia top-N считается **автоматически** при смене FEN — дебаунс 250 мс (как у Stockfish setOption — `useEngine.ts`), всегда в воркере, ровно 1 рейтинг = 1 прогон (быстро, ~0.3-0.5 с).
- Mobile: Maia остаётся в той же вкладке `engine` (прокрутка вниз), без отдельной вкладки.
- Кнопка KS-3579 («Получить рейтинг позиции») **остаётся как опциональный shortcut** в той же подсекции — она решает другую задачу (батч-прогон 14 рейтингов с поиском совпадения со Stockfish), её результат удобен и не дублируется новым блоком.

Альтернативы A (переключатель Stockfish↔Maia в одной панели) и B (две полноценные панели) рассмотрены и отвергнуты — см. §4.

## 4. Сравнение вариантов

|  | **A. Переключатель Stockfish ↔ Maia** | **B. Две отдельные панели** | **C. Maia как подсекция в engine-panel (выбран)** |
|---|---|---|---|
| Одновременная видимость SF + Maia | **нет** (только один движок) | да | **да** |
| Информационная нагрузка | низкая (один блок) | высокая (две жирные панели) | средняя (две секции в одном блоке, разделитель) |
| Сравнение «что Stockfish считает лучшим vs что часто играют» | требует переключения и запоминания | глазами по двум панелям | глазами в одном блоке (соседние строки) |
| Mobile layout | один tab `engine` | нужна вторая вкладка `maia` ИЛИ вторая «секция» в той же | один tab `engine`, scroll |
| Доп. контролы (MultiPV + ELO + engine source) | в шапке шапка слишком плотная (3-4 control'а: source/MultiPV/⚙/Start) | контролы естественно разделены по панелям | контролы Maia в подзаголовке секции, не конкурируют со Stockfish-шапкой |
| Cognitive load (понять что показывается) | низкий (одна структура «линий») | высокий (два блока с разной семантикой строк) | средний (общий контекст — «engine»; внутри явные подзаголовки) |
| Поведение при «выключенном анализе» (toggle Stop в Stockfish) | непонятно: Maia тоже отключается? | независимое управление | Maia может работать независимо от Stockfish (KS-3579 уже так и устроен — Maia в воркере не зависит от SF) |
| Стоимость реализации (frontend) | средне-низкая (один блок, switch state) | высокая (новая panel, mobile-tab, panelStates ещё одна) | **средняя** (одна секция внутри существующей панели, маленькие правки `AnalysisSidebar.tsx`) |
| Стоимость layout (CSS) | низкая | **высокая** (новые grid-области desktop + новая вкладка mobile + bottom-sheet ADR-073 reflow) | средняя (внутренний разделитель + responsive подгонка контролов) |
| Регрессионный риск (mobile bottom-sheet ADR-073) | низкий | **высокий** (новый panel → новый `data-snap`, новый snap-state) | **низкий** (тот же panel, тот же snap-механизм) |

**Отбрасываем A** — главный минус: пользователь не видит обе картины одновременно. Сравнение «Stockfish-лучший vs Maia-человеческий» это **главная польза** связки двух движков; переключатель её убивает. Также непонятно, что делает кнопка `Stop` engine при переключении — двусмысленность управления.

**Отбрасываем B** — главные минусы: (1) две полноценные панели на desktop sidebar занимают много вертикали, выталкивая Archive tree / Moves вниз; (2) на mobile (см. ADR-073: bottom-sheet с 3 snap-точками) добавление второй вкладки или второй секции требует пересмотра `data-snap` и `analysis-mobile-section--*` — это работа на полпайплайна и риск регрессии существующего snap-поведения; (3) дублирование контролов «движок включён / выключен», когда семантически Maia не «engine analysis» в смысле «Stockfish», а скорее «модель поведения».

**Выбираем C** — оптимум по сумме критериев. Maia визуально и функционально соседствует со Stockfish (что справедливо: оба отвечают на вопрос «что играть в этой позиции»), но семантика разная (SF — объективно лучший, Maia — что чаще играют люди такого ELO). Подзаголовок секции делает разницу явной.

## 5. UX-сценарий выбранного варианта (C)

### 5.1. Layout `engine-panel` (desktop, расширенный)

Текстовый макет «как стало»:

```
┌─ Engine ─────────────────────────────── [⚙] [MultiPV − 3 +] [Stop] ▾ ─┐
│ ▸ Stockfish (depth 24, wasm)                                          │
│   +0.42 │ e2e4 c7c5 g1f3 d7d6 ...                                     │
│   +0.18 │ d2d4 g8f6 c2c4 e7e6 ...                                     │
│   +0.05 │ g1f3 d7d5 d2d4 g8f6 ...                                     │
│                                                                       │
│ ─── Human moves (Maia) ─────────────────── [ELO 1500 ▾] [Top 5 ▾] ─── │
│   31.4% │ e2e4                                                        │
│   22.1% │ d2d4                                                        │
│   18.7% │ g1f3                                                        │
│    8.9% │ c2c4                                                        │
│    5.2% │ b1c3                                                        │
│                                                                       │
│ [Получить рейтинг позиции]   ← KS-3579 как shortcut (опционально)     │
└───────────────────────────────────────────────────────────────────────┘
```

Отличия от текущего layout:
- Тонкий разделитель `─── Human moves (Maia) ───` с inline-контролами ELO и Top-N справа.
- Под разделителем — точно такая же структура «строка = число + ход», что у Stockfish-линий. CSS-класс reuse: `stockfish-line` → переименовать в `engine-line`, добавить modifier `engine-line--maia` для цвета процента.
- Кнопка KS-3579 — внизу подсекции, отдельной строкой.

### 5.2. Сценарии пользователя

**A. Просмотр позиции в стартовом состоянии.**
1. Пользователь открывает партию в `/analysis`. Stockfish стартует автоматически (`analysisEnabled = true` по умолчанию).
2. Maia подсекция показывает **placeholder** «Загружаем модель…» при первом обращении (lazy-load ONNX ≈ 3-5 МБ + IndexedDB cache hit на повторных визитах).
3. После загрузки — top-5 ходов для ELO из localStorage (default 1500 при первом визите).

**B. Смена FEN (next/prev/прыжок по дереву ходов).**
1. Stockfish получает новый FEN → новый цикл анализа (как сейчас).
2. Maia — дебаунс 250 мс → один прогон `predictMoves(fen, ELO, ELO)` в воркере → результат через ~0.3-0.5 с.
3. Во время «в полёте» — `engine-line--maia` рендерится с opacity 0.5 или показывается inline-skeleton, чтобы пользователь видел что данные обновляются. Старые цифры не удаляются мгновенно (избегаем «прыжков»).

**C. Смена ELO.**
1. Пользователь дёргает select ELO → `setMaiaElo(1900)` → localStorage.setItem + триггер пересчёта.
2. Тот же FEN, новый прогон, новые top-5 через ~0.3-0.5 с.
3. UI: dropdown sync с локальным state, цифры обновляются после прогона.

**D. Смена Top-N.**
1. Пользователь меняет 3↔5 (или 10, см. §9) → без нового инференса, просто `.slice(0, N)` уже посчитанного `policy`. Мгновенно.

**E. Loading / Error.**
- Loading модели: `engine-line--maia` секция показывает «Загружаем Maia…» одной строкой.
- Error (модель не загрузилась / worker упал): inline-сообщение «Не удалось загрузить Maia» + кнопка «Попробовать снова». Stockfish-блок выше — не затрагивается.

**F. Изменение позиции на доске (drag piece).**
- В режиме «play moves on board» (KS-? — drag-move on analysis): FEN меняется → §B сценарий.

### 5.3. Поведение KS-3579 кнопки

Оставить **как опциональный shortcut** в той же подсекции. Аргументы:
- Maia top-N показывает только один ELO. KS-3579 — батч-прогон 14 рейтингов с поиском **минимального ELO**, на котором best-ход Maia совпадает со Stockfish. Это другая задача (быстро понять «насколько сильный ход надо найти»).
- Кнопка не дублирует функционал основного блока. Пользователь, который не хочет лезть в kроссинг ELO глазами, нажимает «Получить рейтинг» и получает число.
- Внешне — компактная, под top-N списком, не агрессивная.

Альтернатива «удалить кнопку KS-3579 после ввода top-N блока» отвергнута: дополнительные 30 строк UI и 250 мс на нажатие vs пользователь, листающий 14 ELO вручную — кнопка по-прежнему полезна.

## 6. Производительность

### 6.1. Latency бюджет

- **Smena FEN → новые top-N Maia:**
  - Дебаунс 250 мс (overlap с дебаунсом Stockfish setOption).
  - Инференс воркера для batch=1: оценка ~200-500 мс на современном железе (по KS-3577 smoke: батч из 14 ≈ 1 с, значит batch=1 — линейно ~70-100 мс, но добавляется overhead onnxruntime → 200-500 мс реалистично).
  - **Total p50 ~ 500-750 мс от изменения хода до обновления Maia-блока.** Это приемлемо: пользователь читает stockfish-line, к моменту перевода взгляда вниз — Maia готова.
- **Первый показ Maia при открытии страницы:**
  - Сетевая загрузка модели ONNX ~3-5 МБ (cache miss): 1-3 с на хорошем соединении.
  - Init session onnxruntime: ещё ~500-800 мс.
  - **First-paint Maia 2-4 с.** В это время — placeholder.
- **Cache hit (повторное открытие /analysis):** IndexedDB read + session init ~ 500-800 мс. First-paint <1 с.

### 6.2. Frame-блокировки

Worker уже изолирует инференс от main thread (`apps/web/src/lib/maia/maia.worker.ts`). UI остаётся отзывчивым, доска работает.

### 6.3. CPU/memory нагрузка

При каждой смене хода — один worker-инференс. Модель Maia-3 simplified ~10 МБ в RAM. Это **постоянная нагрузка**, в отличие от точечного KS-3579 (раз в N секунд по нажатию). Грубая оценка: при активном кликании по дереву ходов (1 клик в секунду) — ~30-50% одного CPU core в воркере. Это нормально для анализа, но имеет смысл:

- **Опция «Auto / Manual»** (галочка в шапке Maia-подсекции). По умолчанию `Auto` — пересчёт при смене FEN. `Manual` — пересчёт только по кнопке «Refresh». Это для пользователей со слабым железом или режима «листаю партию быстро без анализа».
- **Auto pause при `analysisEnabled = false`** (когда Stockfish выключен). Если пользователь явно нажал Stop — отключаем и Maia (с пометкой «Maia paused, click to compute»). Это сохраняет принцип единого master-toggle.

## 7. Layout desktop и mobile

### 7.1. Desktop

`engine-panel` уже flexible. Добавить:
- Новый dom-блок `.maia-section` внутри `.analysis-panel-body`, под `.stockfish-lines` (или после `.position-maia-rating`).
- Шапка `.maia-section-header` с подзаголовком + control'ами (ELO, Top-N).
- Внутри — `.maia-line` элементы, по аналогии со `.stockfish-line` (тот же row-layout: 60-80px колонка цифры + flexible колонка хода).

CSS — добавление в `apps/web/src/styles/engine.css` (тот же файл, в одном стиле). Темизация — через существующие токены палитры (важно для светлой темы, см. KS-3581).

### 7.2. Mobile

Текущий mobile (см. `AnalysisSidebar.tsx` строки ~580-624 + ADR-073 §7): одна панель с табами `tree | engine | moves`, bottom-sheet с 3 snap-точками. Maia-секция **остаётся в табе `engine`** под Stockfish-линиями. Прокрутка панели уже работает (через `analysis-panel-body--scroll`).

Контролы ELO+Top-N на mobile:
- ELO select — нативный `<select>` (большой touch-target).
- Top-N — два радио-кнопки 3/5 inline.
- На совсем узком экране (`< 400px`) — контролы оборачиваются в новую строку.

### 7.3. Свёртываемость

`panelStates.engine` — общий toggle. **Опционально** в Phase 2: внутри engine-panel — sub-toggle для Maia-секции (chevron, как у `panelStates`), сохраняется в `panelStates.maia`. В MVP — без sub-toggle, Maia всегда видна когда engine-panel открыт.

## 8. Что показывать (контент)

### 8.1. Top-N

Дефолт **5**. Опции: 3 или 5. Не делаем 10 (Maia после top-5 быстро деградирует в шум <2%; экранное место тратится впустую).

### 8.2. Формат строки

`{probability%} │ {san}` — выровненная колонка процента слева (60 px monospace), SAN справа. Без `+` колонки. Без оценочной цветовой подсветки в MVP (см. §8.3).

### 8.3. Цветовая разметка по силе хода (best / blunder)

**Не делаем в MVP** — это требует «привязки» Maia-ходов к Stockfish-оценке (смотреть, попал ли ход в Stockfish top-N или насколько проигрывает в CP). Это полноценная отдельная фича — «human-vs-engine quality grading». Заводим как future-task (см. §10).

В MVP — top-N как есть, монохром (цифры в `var(--c-text-primary)`, выделение top-1 жирностью аналогично Stockfish best-line).

### 8.4. ELO range и шаг

1100..2400 шаг 100 (тот же, что в KS-3579). Default — **1500** (медиана для Lichess blitz, см. KS-3577 рассуждения).

### 8.5. Сохранение ELO между сессиями

localStorage key `analysis.maia.elo` (number). При первом визите — 1500. При смене — `localStorage.setItem('analysis.maia.elo', value)`. Чтение в init hook'е (`useMaiaAnalysisState`).

Дополнительно (опционально, отдельная задача): сохранять Top-N (`analysis.maia.topN`) и режим Auto/Manual (`analysis.maia.mode`).

## 9. Открытые вопросы к пользователю

1. **«Manual» режим** для слабого железа — нужен в MVP или делаем только Auto? Я склоняюсь — Auto-only в MVP (минимум контролов), Manual добавим если кто-то пожалуется.
2. **Pause Maia при Stop Stockfish** — соглашаешься с привязкой к одному master-toggle или хочешь независимое управление? Я склоняюсь — привязка (проще, понятнее).
3. **Top-N default = 5** — ок или хочешь 3? (Меньше визуального шума с 3.)
4. **ELO default = 1500** — ок или брать из профиля пользователя (его реальный рейтинг)? Если из профиля — нужно фоллбэкнуть на 1500 для гостей и для тех у кого рейтинг вне 1100..2400. Реализация чуть дороже.
5. **Цветовая подсветка по силе хода** (best/inaccuracy/blunder через сравнение с Stockfish) — future-фича или хочешь в этом же релизе? Я отложил как §10 P2, но если приоритет — переставлю.
6. **KS-3579 кнопку оставляем** — подтверждаешь? Альтернатива — убрать (Maia top-N делает её менее нужной).
7. **Eval-bar Maia** (win probability в %) — Maia возвращает `winProbability` помимо policy. Показывать ли её рядом с Stockfish eval-bar? Не входит в текущий ADR, но просится — отдельная задача после MVP.

## 10. Декомпозиция на задачи

### Этап A (frontend, 1-1.5 дня) — core UX

**KS-XXXX (создаст координатор): Постоянный анализ Maia в engine-panel.**

1. Новый hook `apps/web/src/hooks/useMaiaAnalysis.ts`:
   - State: `{ elo, topN, lines, status: 'idle'|'loading'|'ready'|'error', error }`.
   - Init: чтение `elo` из localStorage (default 1500).
   - Эффект на смену `fen` или `elo` с debounce 250 мс → `MaiaWorkerEngine.predictMoves(fen, elo, elo)`.
   - Возврат top-N из `policy` (отсортирован по probability desc).
   - Cleanup воркера при unmount.
2. Новый компонент `apps/web/src/components/analysis/MaiaAnalysisSection.tsx`:
   - Props: `{ fen, defaultElo?, defaultTopN? }`.
   - Рендер шапки с подзаголовком + select ELO + select Top-N.
   - Список `.maia-line` с probability + SAN.
   - Состояния loading / error / ready.
3. Встроить `<MaiaAnalysisSection>` в `pages/analysis/AnalysisSidebar.tsx`:
   - Desktop: после `<div className="stockfish-lines">…</div>` и **перед** `<PositionMaiaRatingButton>` (KS-3579 остаётся ниже).
   - Mobile: симметрично в mobile-секции engine-tab.
4. Vitest на hook (мок MaiaWorkerEngine — debounce, смена elo, error case) и на компонент (рендер по статусам).
5. i18n-ключи: `analysis.maia.title` («Human moves (Maia)»), `analysis.maia.elo` («ELO»), `analysis.maia.topN` («Top»), `analysis.maia.loading` («Загружаем Maia…»), `analysis.maia.error`, `analysis.maia.paused`.

**Acceptance:**
- При смене хода Maia top-5 обновляется в течение 1 с (после debounce).
- ELO сохраняется между перезагрузками страницы.
- Vitest зелёный.
- Доска не блокируется во время инференса.

## 11. Не входит в этот ADR

- Backend / API изменения (всё клиентское).
- Замена Stockfish или конкурирующих движков.
- Множественные ELO одновременно (например, top-5 при 1200 vs top-5 при 2000 параллельно) — не нужно в MVP.
- Анализ по всей партии (Maia как «mistake detector» по всем ходам) — отдельная огромная фича.
- Изменения в `PositionMaiaRatingButton` (KS-3579) — кнопка остаётся как есть (KS-3581 стилизация — отдельный live тикет).

## 12. Резюме

Maia становится постоянным анализом — как Stockfish-линии, только под выбираемый ELO и с вероятностями вместо CP-оценки. Размещаем **в той же `engine-panel`** как подсекцию под Stockfish-блоком (вариант C: гибрид между переключателем и двумя панелями). Это сохраняет одновременную видимость двух движков, не плодит панели в sidebar, не ломает mobile bottom-sheet ADR-073. Пересчёт автоматически при смене FEN, debounce 250 мс, инференс в воркере (~0.3-0.5 с). ELO в localStorage. Top-N default 5. Кнопка KS-3579 остаётся как shortcut «найти ELO совпадения со Stockfish одним кликом». Цветовая подсветка по силе хода — future-фича.
