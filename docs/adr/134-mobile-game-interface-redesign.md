# ADR-134: Переработка интерфейса мобильной игровой страницы

## Статус

Предложено (требует ревью координатором и пользователем). Реализация — отдельными задачами после ревью.

## Контекст

Страница `/game/:id` собиралась из десктопных блоков (`GameShell.tsx`) и адаптировалась под мобильный экран простым переключением `flex-direction: row → column` по медиа-запросу `(max-width: 899px)`. За последние правки расчёт высоты доски стал точнее (KS-4256/4275), убраны лишние элементы (KS-4259), учтён MobileBottomBar (KS-4274). Это устранило часть симптомов, но не основной дефект: на портретной мобильной раскладке после доски «складывается» весь sidebar (move-list + actions + chat + game-result), а блок действий после партии не помещается по ширине — кнопки обрезаются, поверх них рисуется FAB AI-ассистента (`ChatWidget`). Свежий пример — KS-4285 (скриншот `/tmp/telegram/326131566_0.jpg`).

Корень проблемы — не «бажная вёрстка отдельного блока», а отсутствие целостного дизайна страницы под узкий экран. Все блоки sidebar'а (ходы, действия, результат, чат) делят остаток высоты после доски, имеют десктопную плотность и десктопные допущения о ширине.

ADR описывает целевую раскладку для портрета и альбомной ориентации в трёх состояниях партии и фиксирует, что из десктопного решения переносить нельзя.

## Что есть сейчас

### Структура DOM (GameShell.tsx)

```
.game-page                                — flex column на ≤899px, gap 12px, padding 48 12 12
├─ .help-btn                              — position: fixed, top 56, right 16
├─ .game-board-area
│  ├─ .bot-fallback-banner (если бот, dismissible)
│  ├─ .player-info.opponent-info          — индикатор цвета + имя + часы, ~40-44px
│  ├─ .board-container                    — квадрат, max-height: calc(100dvh - 180px)
│  ├─ .player-info.player-info-self       — то же снизу
│  └─ {belowBoardBlock?}
├─ .game-h-resizer                        — display:none на mobile
├─ .game-sidebar                          — width 100%, max-width 560, под доской
│  ├─ .move-list                          — h3 "Ходы" + inline список, padding 16, flex:1
│  ├─ .game-actions-top                   — кнопка mute (всегда)
│  ├─ .game-actions                       — Resign/Draw (при status='active')
│  ├─ .game-result                        — итог + 4 кнопки (при finished && !showResultModal)
│  └─ .chat                               — игровой чат (если не bot)
└─ .game-result-modal-overlay             — modal результата (при showResultModal)
```

Поверх всего:
- `ChatWidget` (AI-ассистент, `.chat-widget-btn` — пурпурный FAB) — рендерится в `MainLayout`, не знает о состоянии партии. На `/game/:id` он остаётся видимым и физически перекрывает кнопки `.game-result`.
- `MobileBottomBar` — на `/game/:id` MainLayout скрывает (`hideBottomBar = pathname.startsWith('/game/')`), `useResponsiveBoardSize` это учитывает.

### Перечень дефектов

1. **Post-game кнопки обрезаются по горизонтали.** В `.game-result-actions` контейнер `display: flex; gap: 8px; justify-content: center`, каждая кнопка `.result-btn { display: block; width: 100% }` — без `flex-wrap`. На 320-414px кнопки растягиваются за пределы экрана, текст режется до «ш…», «На гла…».
2. **AI-FAB `ChatWidget` перекрывает post-game действия.** Кнопка `💬` `position: fixed` рендерится у нижнего края, попадает на «Открыть в анализе».
3. **Дублирующий пост-game UI.** При завершении партии открывается модалка `game-result-modal`. Закрытие модалки отрисовывает inline `.game-result` в sidebar (`!showResultModal`) — те же действия в двух разных местах с разной вёрсткой. На мобиле inline-вариант ниже фолда.
4. **Move-list — крупная панель в сайдбаре.** `h3 "Ходы"` + `flex:1` + `padding: 16` + `background`. На post-game у пользователя задача — выбрать действие, а не пересматривать ходы. Панель занимает ~120-200px вертикали, выдавливая кнопки действий за пределы видимой области, в зону FAB.
5. **`mute-toggle` рендерится всегда.** Отдельная FAB-кругляшка в `.game-actions-top` — занимает место и в pre-game, и в post-game, где звук уже не релевантен.
6. **In-game `game-actions` пустоваты.** При `canResign + canOfferDraw` — две кнопки на всю ширину, выглядят растянутыми. Тапнуть «Resign» легко случайно (мгновенная отправка без confirm).
7. **Чат всегда внизу sidebar.** На mobile — ниже фолда, без скролла не видно. Новые сообщения от соперника невидимы, нет тоста или бейджа.
8. **Pre-game состояние не выделено.** При `status='waiting'` страница рендерится так же, как игровая, только часы не тикают. Пользователь не понимает: «идёт поиск, идёт партия с медленным ходом, всё сломалось?».
9. **Landscape ориентация на мобильном — не поддерживается отдельно.** Брейкпоинт `(max-width: 899px)` одинаков для портрета и альбомной. На 700×400 доска не помещается, sidebar уезжает в скролл.
10. **Help-button (fixed top-right).** На mobile в шапке уже плотно — иконки уведомлений, сообщений, темы, языка, профиля. Отдельная плавающая «?» дублирует канал входа в help.
11. **Кнопки fixed-уровня не знают друг о друге.** AI-FAB, help-btn, mobile-bottom-bar (на других страницах), game-result-modal-overlay — каждая решает z-index/position автономно, поверх accumulated stack нет единой координации.

## Решение

### Принципы

- **Один первичный канал действий — нижний sticky action-bar.** Большой палец достаёт нижнюю четверть экрана; верхние кнопки на мобильном — для второстепенных и системных действий (header).
- **Контекст определяет содержимое action-bar.** Pre-game / in-game / post-game — разные наборы кнопок в одном и том же месте.
- **Доска — приоритет.** Всё, что не критично, либо прячется в bottom-sheet, либо помечается компактно. Move-list на mobile — одна строка, не панель.
- **Один источник для результата.** Bottom-sheet, выезжающий снизу. Закрытие — swipe-down. Inline-дублёр в sidebar убираем.
- **Чат — bottom-sheet с тостами.** Не FAB поверх, не панель внизу. Открывается по кнопке в action-bar.
- **AI-ассистент скрыт на `/game/:id`.** Параллельный AI-чат не нужен во время партии.

### Целевая раскладка (портрет)

#### Pre-game (`status='waiting'` или нет state дольше ~1.5 с)

```
┌──────────────────────────────┐  Header (sticky, 44+safe-top)
│ Kingside BETA   🔔 ✉ ☾ EN 👤 │
├──────────────────────────────┤
│ ⚫ Соперник           — : —   │  player-bar opponent (часы dim)
├──────────────────────────────┤
│ ┌──────────────────────────┐ │
│ │     ⏳ Ищем соперника…    │ │  overlay над доской (центр):
│ │     ─────                │ │  - вращающийся индикатор
│ │     контроль 5+0        │ │  - подпись режима/контроля
│ │                          │ │  - кнопка [Отменить] на action-bar
│ │   (доска бледная)        │ │
│ └──────────────────────────┘ │
├──────────────────────────────┤
│ ⚪ Вы                — : —    │
├──────────────────────────────┤
│        [Отменить поиск]      │  action-bar (одна primary)
└──────────────────────────────┘
```

#### In-game (`status='active'`)

```
┌──────────────────────────────┐  Header (44+safe-top)
├──────────────────────────────┤
│ ⚫ Соперник [⚡]      2:49    │  opponent-bar (active = акцент)
├──────────────────────────────┤
│                              │
│                              │
│         CHESSBOARD           │  квадрат от min(vw, доступной_высоты)
│                              │
│                              │
├──────────────────────────────┤
│ ⚪ Вы                3:00    │  self-bar (active = акцент)
├──────────────────────────────┤
│ 1.e4 c5 2.Nf3 Nc6  ←→        │  compact move-strip, scroll-x, 28-32px
├──────────────────────────────┤
│ [⚐ Сдаться] [½ Ничья] [💬²] [⋮] │  action-bar 4 кнопки (sticky+safe-bottom)
└──────────────────────────────┘
```

- **Move-strip:** 1 строка, горизонтальный скролл, последний ход подсвечен (`.current`), `scroll-into-view` на новом ходе. Без заголовка «Ходы», без панели и фона.
- **Action-bar:** 4 кнопки по ~25% ширины, min-height 48px, ≥44px touch-area, иконка + короткий лейбл; на 320-359px — icons-only.
- **Кнопка `💬`:** бейдж с числом непрочитанных. Тап — bottom-sheet чата.
- **Кнопка `⋮ Ещё`:** bottom-sheet с: Mute / Help / Settings доски / Вернуться в лобби.
- **Resign:** требует подтверждения. Первый тап → бейдж «Подтвердите» под кнопкой на 2 с / второй тап → отправка. На десктопе оставляем как есть.

#### Post-game (`status='finished'`)

```
┌──────────────────────────────┐  Header
├──────────────────────────────┤
│ ⚫ Соперник           —       │  часы dim после конца партии
├──────────────────────────────┤
│         CHESSBOARD           │  (без анимаций часов, последний ход подсвечен)
├──────────────────────────────┤
│ ⚪ Вы                 —       │
├──────────────────────────────┤
│ 1.e4 c5 2.Nf3 Nc6  ←→        │  тот же move-strip
├──────────────────────────────┤
│ ┌──────────────────────────┐ │
│ │     ─── 🔵 ───            │ │  bottom-sheet (slide-up from action-bar)
│ │   Партия завершена       │ │  - заголовок крупный
│ │   Ничья · 1480→1481(+1)  │ │  - 1 строка с исходом + рейтинг
│ │                          │ │  - 2×2 grid действий:
│ │  [Реванш ]  [В анализ]   │ │
│ │  [Новая  ]  [На главную] │ │  - swipe-down для сворачивания
│ └──────────────────────────┘ │
└──────────────────────────────┘
```

- Bottom-sheet **заменяет и модалку, и inline-блок** в sidebar. Один путь — один UI.
- Сворачивается по swipe-down → action-bar превращается в один pill «Партия завершена ▲» (re-open).
- Раскрытие — тап по pill или по итогу партии в sidebar.
- Grid 2×2 на портрете; на ≥414px — 4 в ряд если по содержимому помещается.
- Tournament-возврат (`tournamentReturn`) занимает primary-слот, остальные — secondary.

### Чат и уведомления

- **Игровой чат — bottom-sheet.** Открывается по кнопке `💬` в action-bar. Высота — 50-70% viewport. Закрытие — swipe-down или ✕. На время открытия action-bar заменяется на input для сообщения + кнопку «Отправить» (sticky над безопасной зоной).
- **Тосты непрочитанных:** при закрытом sheet'е и `status='active'` — toast у верхнего края `.player-info.opponent-info` на 4 с, кликабельный (открывает sheet). Не перекрывает доску. На post-game тосты не показываем — пользователь занят выбором действия.
- **Бейдж на кнопке `💬`:** число непрочитанных, сбрасывается при открытии sheet'а.
- **AI-ассистент (`ChatWidget`):** скрыт на `/game/:id`. В `MainLayout` уже есть `hideBottomBar = pathname.startsWith('/game/')` — добавляется зеркальное `hideAssistantFab`. При желании AI оставить на странице — выносить в `⋮ Ещё` (но по умолчанию off).
- **Системные нотификации (предложение ничьей, реванш):** inline-баннер над action-bar, не модалка. Уже частично реализовано (`.draw-offer`), нужно вынести из sidebar в фиксированное место над action-bar.

### Адаптив и брейкпоинты

| Брейкпоинт                  | Поведение                                                       |
|-----------------------------|-----------------------------------------------------------------|
| ≤319px                      | Не поддерживаем (под Kingside нет таких клиентов в аналитике).  |
| 320-374px (iPhone SE 1G)    | Action-bar icons-only, move-strip компактный, доска ≈304px.     |
| 375-413px (iPhone mini)     | Action-bar icons + короткий лейбл. Bottom-sheet result — 2×2.   |
| 414-767px                   | Стандартный mobile. Полные лейблы. Бейдж непрочитанных полный.  |
| 768-899px (tablet portrait) | Та же одна колонка, но action-bar может быть 5-6 кнопок в ряд.  |
| ≥900px                      | Текущий desktop (две колонки + sidebar). Не трогаем.            |

**Landscape mobile (`orientation: landscape and max-height: 500px`):**

```
┌─────────────────────────┬─────────────────────────┐
│ ⚫ Opp           2:49    │ 1. e4    c5             │  компактный move-list
├─────────────────────────┤  2. Nf3   Nc6            │  две колонки
│                         │  ...                    │
│       BOARD             │                         │
│       (h ≤ 90vh)        │                         │
│                         ├─────────────────────────┤
│                         │ [Resign] [Draw] [💬] [⋮]│  action-bar (правый блок)
├─────────────────────────┤                         │
│ ⚪ You           3:00    │                         │
└─────────────────────────┴─────────────────────────┘
```

- Доска — слева, высота `min(95vh, vw/2)`. Sidebar (часы соперника? — над доской слева, ходы и actions — справа).
- Реализация — отдельный media-query, без переписывания React-структуры (вся разница в CSS, ширины и порядок flex).

**Safe-areas:**

- Header: `padding-top: env(safe-area-inset-top, 0)` (уже есть в layout.css).
- Action-bar: `position: sticky; bottom: 0; padding-bottom: env(safe-area-inset-bottom, 0)` + min-height 56px + safe-area.
- Доска (`useResponsiveBoardSize`) — пересчёт под action-bar (вычесть его высоту так же, как сейчас вычитается MobileBottomBar). Уже есть параметризация через `extraSubtract`/`hideMobileBottomBar` — переиспользуем механизм.
- Bottom-sheet (результат, чат): `border-radius: 16 16 0 0`, тащимая «ручка» сверху (`width: 36; height: 4`), backdrop-blur подложкой.

### Жесты и эргономика

- **Зоны досягаемости.** Большой палец на 6"-телефоне достаёт нижнюю треть экрана. Action-bar и bottom-sheet рассчитаны на эту зону. Header — для редких/системных действий.
- **Touch targets ≥ 44×44** (Apple HIG / Material). Уже есть в `@media (max-width: 899px)` для `.game-actions button` (min-height: 44px) — переносим то же правило на action-bar.
- **Tap по доске vs UI:** доска — единственная зона, где tap делает выбор клетки. Все остальные тапы — на кнопки/сэйфы; нет двусмысленностей. Premove работает как сейчас (drag/click → запоминается, применяется на нашем ходу).
- **Swipe-down** на bottom-sheet result/chat — closes/collapses.
- **Swipe-left/right на move-strip** — не вводим (риск конфликта со скроллом списка). Навигация по ходам — отдельная фича уровня анализа, не игры.
- **Длительный тап на фигуре** — не вводим (legal-moves подсветка уже включается одним тапом, см. `useBoardHighlights`).
- **Pull-to-refresh** — отключаем на `/game/:id` (`overscroll-behavior: contain` на `.game-page`). Случайный pull прерывал бы партию визуально.
- **Resign confirm.** Двухтап с таймером 2 с (визуальный бейдж «Подтвердите?»). Защищает от случайного тапа в action-bar.

### Что НЕ переносим с десктопа

1. **`.game-sidebar` как блок.** На mobile — нет sidebar; контент распределён по 3 зонам: header (системное), под доской (move-strip), action-bar + bottom-sheets (действия/чат/результат). Перенос десктопного sidebar в виде «развалившейся колонки» — корень текущих проблем.
2. **Inline `.game-result`** в потоке sidebar'а. Один источник правды — bottom-sheet. Inline дублирует и противоречит.
3. **`.game-h-resizer`** (manual width resizer) — не имеет смысла на mobile, скрыт уже сейчас, не воскрешаем.
4. **`.help-btn` fixed top-right.** Help переезжает в `⋮ Ещё` action-bar'а. Уменьшаем число fixed-элементов поверх доски.
5. **AI-FAB `ChatWidget`** на странице игры. Не контекстуально, физически перекрывает action-bar.
6. **`.mute-toggle` отдельной кнопкой в action-bar'е.** Переезжает в `⋮ Ещё`. На уровне частоты использования это «один раз перед партией», не оправдывает 25% action-bar'а.
7. **Десктопный `.move-list`** (panel с заголовком, padding 16, flex:1). Заменяется compact move-strip. h3 «Ходы» не нужен — содержимое самоочевидно.
8. **Модалка результата** (`game-result-modal-overlay` центрированная). Заменяется bottom-sheet'ом, лучше попадает в зону пальца, легче закрыть.

## Альтернативы

1. **Точечная правка пост-game ряда (KS-4285) + сокрытие AI-FAB.** Дешёво (1-2 часа), но не убирает первопричину — fragmented mobile UX, чат-сообщения соперника по-прежнему ниже фолда, in-game action-row остаётся «маркетингово растянутым», pre-game состояние не выделено. Откладывает повторение проблемы при следующей правке `GameShell`.
2. **Перенос на готовый mobile-UI-toolkit (Ionic / Konsta / Framework7).** Решает разом, но: лишний рантайм, чужие стили, конфликт с react-chessboard, перевыезд всей кодовой базы. Один разработчик — не оправдано.
3. **Отдельный mobile-роут с собственным компонентом (`<MobileGamePage>`).** Меньше CSS-связности, но дублирование state-логики и риск рассинхрона с десктопом. Текущий путь — общий `GameShell` с разными media-query / conditional рендером по `useIsMobile()` — дешевле в поддержке.

Выбран компромисс: оставляем `GameShell` единым React-компонентом, но (а) вводим `useIsMobile()` хук, (б) для mobile рендерим альтернативную раскладку (action-bar + bottom-sheets + compact move-strip) внутри того же компонента, (в) выделяем `<GameActionBar>`, `<GameBottomSheet>`, `<GameMoveStrip>` как переиспользуемые блоки. Без новых зависимостей.

## Последствия

### Положительные

- Post-game кнопки помещаются на любой ширине от 320px.
- AI-FAB не пересекается с игровым UI.
- Чат соперника становится видимым (через тосты и bottom-sheet).
- Pre-game состояние — явное.
- Landscape — рабочий вид, а не «доска и скролл».
- Единый источник для пост-game действий (нет дублирующего inline-блока).
- Уменьшается количество fixed-элементов поверх доски (help-btn → переезжает, AI-FAB → скрыт).

### Отрицательные / стоимость

- Реализация — несколько фронтенд-задач (см. раздел «Задачи реализации»), суммарно ~5-9 дней работы одного разработчика, частично на CSS, частично на React.
- `useResponsiveBoardSize` потребует ещё один параметр (`hasActionBar`) или сразу учёт sticky action-bar по умолчанию на mobile.
- Существующие e2e/тесты на `game-result-modal-overlay` и inline-кнопки нужно переписать на bottom-sheet (data-testid сохраняем, расположение меняется).
- Часть пользователей привыкла к центрированной модалке результата — bottom-sheet это новое поведение, нужно подсветить в release-note.
- AI-ассистент во время игры станет недоступен — если есть метрика использования, провалидировать у marketing/coordinator, что это допустимо.

### Технические инварианты, которые сохраняем

- `GamePage.tsx` (state-логика, WS-подписки) не меняется. ADR — про визуальный shell.
- `GameShell` API (пропсы) не меняем, чтобы `/play/local-bot` и другие потребители не падали.
- `useResponsiveBoardSize` остаётся источником истины для высоты доски, добавляем параметр(ы) — не заменяем.
- На десктопе (≥900px) — никаких изменений. Все правки за media-query.

## Задачи реализации (после ревью ADR)

Координатор разбивает на отдельные тикеты frontend/layout:

1. **Post-game bottom-sheet** — заменить `.game-result-modal-overlay` на slide-up sheet с swipe-down close. Убрать рендер inline `.game-result` в `.game-sidebar` на mobile. Один новый компонент `<GameResultSheet>`.
2. **Mobile action-bar** — sticky-positioned ряд из 4 кнопок (`<GameActionBar>`), контекстный (pre/in/post-game). Учёт safe-area-inset-bottom. Пересчёт высоты доски (`useResponsiveBoardSize` + новый параметр).
3. **Compact move-strip** — `<GameMoveStrip>` для mobile, 1 строка с горизонтальным скроллом и `scroll-into-view` на последний ход. Заменяет `.move-list` под `(max-width: 899px)`.
4. **Чат как bottom-sheet + toast** — `<GameChatSheet>`, бейдж непрочитанных на кнопке `💬`, toast-уведомление об новом сообщении при закрытом sheet'е. Inline `.chat` в sidebar остаётся на desktop ≥900px.
5. **Скрытие AI ChatWidget на `/game/:id`** — флаг `hideAssistantFab` в `MainLayout`, зеркальный к `hideBottomBar`. Минимальный тикет (5-10 строк).
6. **Pre-game placeholder** — overlay над доской при `status='waiting'` >1.5 с. Action-bar показывает «Отменить поиск» если применимо.
7. **Resign confirm на mobile** — двухтаповое подтверждение в action-bar. На desktop поведение прежнее.
8. **Landscape mobile layout** — media-query `(orientation: landscape) and (max-height: 500px)`. Две колонки. Отдельный тикет.
9. **Удаление `.help-btn` fixed-кругляша на mobile** — перенос в `⋮ Ещё`. На desktop fixed-кнопка остаётся.
10. **Регрессы тестов** — обновить `GameShell.test.tsx` (если есть) и e2e-сценарии под bottom-sheet.

Порядок выполнения: 5 → 1 → 2 → 3 → 6 → 4 → 7 → 9 → 8 → 10. Пункты 1-3 закрывают основную боль KS-4285. Остальное — улучшение поверх.
