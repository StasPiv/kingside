# ADR-145: Насыщение страницы `/play` (lobby) контентом из уже существующих модулей

**Статус:** Черновик на ревью координатором
**Дата:** 2026-06-25
**Задача:** KS-4664
**Связанные ADR / задачи:** ADR-128 §6.8 (публичные эндпоинты лобби), KS-4264 (`/landing/stats`), KS-4153 (TC для бота), KS-4646 (промо «Chess lectures»), KS-4192 (`/lectures/public`).

## 1. Контекст

### 1.1 Что есть сейчас

`apps/web/src/pages/PlayPage.tsx` (≈500 строк) собирается из трёх блоков:

- Центр: карточка «Быстрая игра» — табы категорий (Bullet/Blitz/Rapid/Classical/Свои) + сетка из 3–4 TC-пресетов одной категории + рейтинг-фильтр + кнопка «Играть».
- Правая колонка: «Играть с другом» (свёрнутая) + «Играть с ботом» (свёрнутая, со слайдером уровня и выбором цвета).

На скриншоте пользователя (`/tmp/telegram/326131798_0.jpg`) видно: при ширине ≈1280px центральная карточка занимает ~35% ширины, справа второй блок ~25%, остальное (≈40%) — пустой светло-серый фон. Под основным контентом — белая пустота до низа viewport.

**Важный факт:** `App.tsx` строка 476 — `HomePage` для авторизованного пользователя редиректит на `/play`. То есть это **домашняя страница залогиненного юзера**: каждый вход в Kingside начинается отсюда. Пустота воспринимается как «здесь нечего делать».

### 1.2 Образец (lichess)

`/tmp/telegram/326131797_0.jpg`:
- Центр: 12 одинаковых квадратных кнопок TC + «Своя игра» (грид 3×4, занимает ≈45% ширины).
- Слева: лента стримеров (2 строки) + 3 баннера активных арен.
- Справа: 3 кнопки («Создать запрос на игру», «Бросить вызов другу», «Сыграть с компьютером»).
- Под центром: 4 карточки контента — 3 «Study/Coach» + «Задача дня» (с маленькой доской).
- Низ: 2 баннера («Поддержать проект» + «Swag Store»).
- Микростатистика справа от грида: «89 553 игроков · 39 688 партий».

### 1.3 Что хочет пользователь

Не копировать lichess дословно — насытить лобби тем, что **уже есть** в проекте. Список идей в задаче.

### 1.4 Что НЕ в скоупе

- Контент, которого ещё нет (стримеры, команды, лента — не создавать ради лобби).
- Редизайн навигации / шапки.
- Изменения логики matchmaking / challenges / bot-game (только их UI-входы).
- A/B-тесты, аналитика плотности.

## 2. Решение (кратко)

1. **Не строить лобби как один монолит.** Раскладка превращается в 4 зоны: `aside` (узкая левая), `main` (центр, сетка TC + правая панель действий), `strip` (контент-лента под сеткой), `header-stats` (счётчик онлайн в заголовке). Каждая зона — независимый компонент со своим источником данных.
2. **Сетка TC в стиле lichess.** Заменить узкую карточку «Быстрая игра» гридом 3×4 квадратных кнопок: 11 TC из существующего `PRESETS` + «Своя игра». Категории не tabs, а подпись внутри кнопки (мелкий шрифт). Клик = выбрать; второй клик / Enter = запустить поиск (или сразу запуск — обсуждается, см. §3.2).
3. **Контент-лента под гридом.** 4 карточки в ряд: задача дня · свежая лекция · свежий блог-пост · live-партия (featured broadcast). Все источники данных **уже есть** в API.
4. **Левая колонка `aside` (desktop ≥1280px).** Активные турниры + live-трансляции. Если пусто — не рендерится. На mobile/tablet — отсутствует.
5. **Правая колонка остаётся, но сворачивается в 2 узкие кнопки.** «Играть с другом» и «Играть с ботом» — как в lichess. По клику разворачивается панель с настройками.
6. **Микро-статистика в заголовке.** `N игроков онлайн · M партий идёт` из `/landing/stats` (KS-4264) — обновление раз в 30 с.
7. **Минимум нового backend.** Из 4 карточек контент-ленты три закрываются существующими эндпоинтами. Один (`featured broadcast game`) можно реализовать чисто на фронте через цепочку существующих `/broadcasts` → `/broadcasts/:id/rounds`. Опционально — позже завести `/lobby/summary` для одного запроса.

## 3. Детали

### 3.1 Layout

Desktop ≥1280px:
```
┌─────────────────────────────────────────────────────────────────────┐
│ «Играть»                          89 553 онлайн · 12 437 партий    │  ← LobbyHeader
├──────────┬──────────────────────────────────────────────┬───────────┤
│          │ [1+0] [2+1] [3+0]                            │ 👥 Друг   │
│ Турниры  │ [3+2] [5+0] [5+3]                            │           │
│ (top-3)  │ [10+0][10+5][15+10]                          │ 🤖 Бот    │
│          │ [30+0][30+20][Своя]                          │           │
│ Live     │                                              │           │
│ broadcast│ ☐ Фильтр рейтинга  [Играть] (active TC)      │           │
│ (1-2)    │                                              │           │
├──────────┴──────────────────────────────────────────────┴───────────┤
│ [Задача дня] [Свежая лекция] [Свежий блог] [Live broadcast game]    │  ← LobbyContentStrip
└─────────────────────────────────────────────────────────────────────┘
```

Tablet 900–1279px: `aside` уходит, остальное растягивается на 12 колонок.

Mobile <900px: вертикальный стек:
1. LobbyHeader (онлайн-счётчик компактный)
2. Сетка TC (3×4, кнопки крупные)
3. Кнопка Play
4. «Друг» + «Бот» (свёрнутые карточки, как сейчас)
5. LobbyContentStrip — горизонтальный скролл-снап (4 карточки)
6. (опц) Турниры/трансляции компактным списком

CSS-сетка — `grid-template-areas`, как в `game.css` (KS-4621). Зона `layout` берёт это как отдельный тикет.

### 3.2 Сетка TC

11 пресетов из существующего `PRESETS` (`useTimeControl.ts`): `1+0`, `2+1`, `3+0`, `3+2`, `5+0`, `5+3`, `10+0`, `10+5`, `15+10`, `30+0`, `30+20`. Двенадцатый слот — кнопка «Своя игра» (показывает `<CustomTcModal>` поверх лобби).

Кнопка ≈140×100 px (desktop) / 100×80 (mobile), внутри:
- Крупная цифра: `5+3`
- Мелкая подпись: `Блиц` (категория)
- Подсветка `active`-состояния — текущий выбор.

**Поведение клика — два варианта, выбирает координатор:**

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Клик = выбрать; кнопка «Играть» внизу запускает поиск (текущее поведение проекта) | Привычно для пользователя; рейтинг-фильтр виден заранее | На один ход медленнее; кнопка «Играть» — лишний клик |
| B. Клик = сразу запуск поиска (как lichess) | Один клик — играешь | Рейтинг-фильтр и custom-TC становятся «дополнительными настройками» (опц. иконка ⚙ рядом с сеткой) |

Рекомендация: **A**, но с горячей клавишей `Enter` после выбора → поиск. Радикальное B можно сделать вторым шагом по фидбэку.

Custom-TC (текущий таб): остаётся как модалка по клику на «Своя игра». Сохранённые controls (`/users/me/time-controls`) — внутри той же модалки. UI чистится, перенос логики из текущей `play-section--quick`.

### 3.3 Контент-лента (`LobbyContentStrip`)

| Карточка | Источник данных | Хук на фронте | Бэкенд |
|---|---|---|---|
| Задача дня | `GET /puzzles/daily` | новый `useDailyPuzzle` | **есть** (`DailyPuzzleController`) |
| Свежая лекция | `GET /lectures/public?limit=1&order=startedAt-desc` | существующий `usePublicLectures` (использовать с `limit=1`) | **есть** (KS-4192) |
| Свежий блог-пост | `GET /blog/posts?limit=1&locale=<i18n>` | новый `useLatestBlogPost` | **есть** (`BlogController`) |
| Live-партия (featured) | `GET /broadcasts?status=live&limit=1` → `GET /broadcasts/:id/rounds` → берём первую игру первого active round | новый `useFeaturedLiveGame` | **есть** (через `broadcast-service`) |

Каждая карточка — `<Link to=...>`, при пустом ответе карточка показывает skeleton 1.5 c и затем «нет данных» / скрывается. Layout сохраняется (4 слота фиксированы, чтобы не прыгало).

Альтернатива (упрощение): backend-задача `GET /lobby/content` — один запрос вернёт все 4 поля. Снижает latency на 3 RTT, но добавляет ещё один эндпоинт. Без него фронт делает 4 параллельных запроса в `Promise.all`, кэшируется в `react-query`/локальном state на 60 с. **Рекомендация: начать без агрегатора, добавить если профилирование покажет проблему.**

### 3.4 Левая колонка (`LobbyAside`)

| Блок | Источник | Когда скрывать |
|---|---|---|
| Активные турниры | `GET /tournaments/top-active` | если ответ пустой |
| Live-трансляции | `GET /broadcasts?status=live&limit=2` | если ответ пустой |

Каждый блок — лента из 2-3 компактных карточек, ссылка «Все →» в конец. Если оба блока пусты — `aside` не рендерится, центральная зона расширяется (через CSS `:empty` сосед или JS-флаг).

На mobile/tablet `aside` отсутствует (`display:none` через `@media max-width: 1279px`).

### 3.5 Правая колонка (действия)

Сужается до двух компактных кнопок, как в lichess:
- «👥 Играть с другом» — раскрывает список онлайн-друзей + Invite (текущая логика `friendOpen`).
- «🤖 Играть с ботом» — раскрывает уровень + цвет + TC (текущая логика `botOpen`).

Логика хуков `useChallenge`, `useBotGame`, `useMatchmaking` не меняется.

### 3.6 Микро-статистика в заголовке

`<LobbyHeaderStats>` под `<h1>Играть</h1>`:
```
89 553 игрока онлайн · 12 437 партий идёт
```
- Источник: существующий `GET /landing/stats` (KS-4264, кэш Redis 60 с + HTTP `max-age=30`).
- Обновление: на mount + `setInterval(30_000)`.
- Если запрос упал — не рендерится (silent fail).

### 3.7 «Meet our coaches»

В задаче упомянуто как опция. **Рекомендация: отложить.** Причины:
- На FeaturesPage (`/features`) этот блок уже есть и работает (KS-4646).
- Лобби — место «начать играть»; промо тренеров на пути «выбрать TC → играть» отвлекает.
- Если оставить — компактная карточка «3 тренера» в `aside` или внутри `LobbyContentStrip` (5-я карточка).

Решение оставить за координатором — если включаем, появляется отдельная задача F7 (см. ниже).

### 3.8 Что мы НЕ делаем сразу

- **Стримеры / лента стримеров** — нет источника. Делать «потом, если будет интеграция с Twitch/YouTube».
- **Леаборд команд** — `teams` модуля в проекте нет.
- **«Зал ожидания» (список соискателей)** — у нас pool-matchmaking, не open-challenges. Если когда-нибудь будут open-seeks (KS-???), это станет третьим блоком в центре.
- **Перепалка / chat-лобби** — отдельная фича.

## 4. Объём работ (для координатора)

### Frontend (приоритет P1 — нужно для «насытить лобби»)

- **F1.** Сетка TC 3×4 (11 пресетов + «Своя игра»), категории в подписи кнопки, поведение по варианту A (§3.2). Заменяет существующий блок `.play-section--quick`. Custom-TC мигрирует в модалку. Рейтинг-фильтр сохраняется компактной строкой над кнопкой Play. ~4-6 ч.
- **F2.** `LobbyContentStrip` — 4 карточки (daily puzzle, lecture, blog, broadcast game), 4 хука/запроса параллельно, skeleton-состояние, ссылки. ~5-7 ч.
- **F3.** `LobbyHeaderStats` — компактный счётчик `/landing/stats` с авто-обновлением. ~1-2 ч.

### Frontend (приоритет P2 — добавляет насыщения)

- **F4.** `LobbyAside` — активные турниры + live-трансляции, скрытие если пусто. ~3-4 ч.
- **F5.** Сворачивание правой колонки в lichess-стиле (две узкие кнопки → раскрывающиеся панели). ~2-3 ч.

### Layout / CSS

- **L1.** Адаптивная сетка `grid-template-areas` для трёх брейкпоинтов (mobile / tablet / desktop). Корректное скрытие `aside`/`strip` при пустоте. Skeleton-стили карточек. Зона `layout`, без правки логики. ~3-4 ч.

### Backend (приоритет P3 — опционально, добавляет производительности/удобства)

- **B1.** `GET /coaches/featured?limit=3` — компактный API для карточки тренеров, если §3.7 включён. ~2-3 ч.
- **B2.** `GET /broadcasts/featured-game` — 1 эндпоинт-шорткат вместо цепочки 2 запросов на фронте. Опц. ~2 ч.
- **B3.** `GET /lobby/summary` — агрегированный ответ всех источников (stats + daily puzzle + lecture + blog + broadcast game + tournaments). Параллельные запросы внутри + Redis-кэш 30 с. Опц., только если профилирование покажет, что 4-6 запросов на mount — проблема. ~4-5 ч.

### Опционально

- **F6.** Подключение «Meet our coaches» (5-я карточка / aside-блок). Зависит от B1. ~2 ч.

### Итого

- Обязательный (P1): F1 + F2 + F3 + L1 = **~13-19 ч**
- Желательный (P2): F4 + F5 = **+5-7 ч**
- Опциональный backend: B1/B2/B3 = **+2-10 ч** в зависимости от выбора

Список конкретных тикетов формирует координатор. Распределение по исполнителям:
- F1, F2, F3, F4, F5 → `frontend`
- L1 → `layout`
- B1, B2, B3 → `backend`

## 5. Открытые вопросы (для координатора до старта)

1. **Поведение клика по TC-кнопке** — вариант A (рекомендован, §3.2) или B?
2. **Карточка «Meet our coaches»** — включать в P1/P2 или отложить (§3.7)?
3. **Агрегатор `/lobby/summary`** — делать сразу в первой итерации или отложить до замеров?
4. **«Партия дня» vs «live broadcast game»** — в задаче упомянуто и то, и то. Это одно и то же (live-партия из текущей трансляции), или хочется отдельной курируемой «партии дня» (требует ручного выбора админом + backend для пометки → отдельный тикет)?
5. **Прежний рейтинг-фильтр и Custom-TC** — оставить как было (раскрывающаяся секция), переехать в отдельную модалку, или объединить в одну «настройки игры» модалку?
