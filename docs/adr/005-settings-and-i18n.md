# ADR-005: Страница настроек и система локализации

**Статус:** Принято
**Дата:** 2026-03-07
**Контекст задачи:** KS-39

## Контекст

В приложении отсутствует страница настроек пользователя и система локализации. Весь текст интерфейса захардкожен на русском языке. Необходимо добавить возможность переключения языка (по умолчанию английский) и страницу для управления настройками.

## Решения

### 1. Хранение языка — поле `locale` в таблице `users`

Добавляем поле `locale` непосредственно в модель `User`, а не в отдельную таблицу.

**Причины:**
- Простота — одно поле, один запрос
- Locale нужен при каждой загрузке приложения (GET /api/auth/me), отдельная таблица создаёт лишний JOIN
- Одного разработчика — минимум абстракций
- Если в будущем настроек станет много — можно вынести в отдельную таблицу

**Альтернатива отвергнута:** Отдельная таблица `user_preferences` — избыточна для одного поля.

### 2. Библиотека локализации — react-i18next

**Причины:**
- Стандарт де-факто для React
- Хуки (`useTranslation`), интерполяция, плюрализация
- Минимальный бойлерплейт
- Большое сообщество и документация

**Альтернативы:**
| Библиотека | Причина отказа |
|-----------|----------------|
| react-intl (FormatJS) | Более сложный API, избыточен для двух языков |
| Свое решение | Нет смысла писать то, что уже решено |
| lingui | Меньше сообщество, сложнее setup |

### 3. Структура переводов — вложенный JSON по секциям

Переводы организованы по секциям UI (nav, auth, lobby, game, settings) во вложенной JSON-структуре. Один файл на язык.

**Причины:**
- Удобная навигация по секциям
- Легко искать нужный ключ
- Достаточно для текущего масштаба приложения

### 4. Определение языка — приоритет: БД > localStorage > "en"

Для авторизованных — язык из БД (поле `locale`).
Для неавторизованных — localStorage или `navigator.language` с fallback на `"en"`.

**Причины:**
- Авторизованный пользователь получает свой язык на любом устройстве
- localStorage кэширует выбор, чтобы не мерцал интерфейс при загрузке
- `"en"` — безопасный fallback

### 5. API — PATCH эндпоинты на существующем UserController

```
PATCH /api/users/me/settings  — обновление locale
PATCH /api/users/me/password  — смена пароля
```

**Причины:**
- PATCH — частичное обновление, семантически корректно
- `/me/` — текущий пользователь по JWT, не нужно передавать ID
- Расширяем существующий контроллер, не создаём новый модуль

## Последствия

- Миграция БД — добавление поля `locale` в таблицу `users`
- Обновление типа `User` в shared пакете — добавить `locale`
- Все захардкоженные строки на фронтенде нужно заменить на ключи `t()`
- Английский язык становится языком по умолчанию (переход с русского)
- Зависимость от i18next и react-i18next в frontend
