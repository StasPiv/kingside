# ADR-011: Раздел «Мастерская» — отдельная страница вместо модального окна

**Статус:** Принято
**Дата:** 2026-03-14
**Задача:** KS-467

## Контекст

Предыдущая реализация (KS-464–466) оформила «Мастерскую» как тизер на лобби-странице с намёком на дальнейшее развитие. Страница `/workshop` была заглушкой. Пользователи ожидают полноценного раздела для анализа партий и работы с PGN.

## Решение

Реализовать `/workshop` как самостоятельную полноценную страницу с четырьмя секциями: новая партия, список партий, турниры, загрузка PGN.

**Ключевые решения:**

1. **Нет модального окна** — страница-заглушка убирается, контент выносится на полноценный маршрут `/workshop`.

2. **Переиспользование существующей инфраструктуры** — новых API эндпоинтов не создаётся. Все данные доступны через существующие эндпоинты (`GET /api/games/my`, `GET /api/tournaments/top-active`, `POST /api/games/bot`).

3. **Переиспользование компонентов** — логика матчмейкинга и выбора контроля времени из LobbyPage выносится в переиспользуемые хуки/компоненты, не дублируется.

4. **Турниры как mock** — секция турниров остаётся на mock-данных. Реальная система турниров — отдельный эпик.

5. **PGN Upload через state** — PGN файл передаётся на страницу анализа через React Router state (`useNavigate({ state: { pgn } })`), без сохранения на сервере.

## Альтернативы, которые не выбраны

- **Вкладки вместо секций** — отклонено в пользу единой прокручиваемой страницы (проще, меньше состояния).
- **Отдельный API для Workshop** — избыточно, существующих эндпоинтов достаточно.
- **Хранение PGN на сервере при загрузке** — избыточно для первой итерации; анализ загруженного PGN не требует сохранения партии.

## Последствия

- Frontend: Одна задача — реализация WorkshopPage с компонентами (см. KS-467-workshop-redesign.md)
- Backend: Нет изменений
- LobbyPage: Тизер Workshop остаётся (ссылка на `/workshop`), логика PGN upload переносится в WorkshopPage
