# ADR-001: Выбор стека технологий

**Статус:** Принято
**Дата:** 2026-03-07
**Контекст задачи:** KS-6

## Контекст

Kingside — шахматная онлайн-платформа (аналог chess.com). Разработка ведётся одним разработчиком, ресурсы сервера ограничены. Нужен стек, который позволит быстро итерировать и обслуживать real-time взаимодействие (шахматные партии, чат).

## Решение

### Бэкенд: Node.js + TypeScript + NestJS

- **Node.js** — неблокирующий I/O, идеален для WebSocket-соединений и real-time приложений
- **TypeScript** — строгая типизация, общий язык с фронтендом, меньше переключений контекста для одного разработчика
- **NestJS** — модульная архитектура, встроенная поддержка WebSocket (gateway), DI, валидация, хорошая документация

### Фронтенд: React + TypeScript + Vite

- **React** — широкая экосистема, большое сообщество
- **Vite** — быстрая сборка, HMR
- **chessboard.js / react-chessboard** — готовые компоненты шахматной доски
- **chess.js** — валидация ходов на клиенте

### База данных: PostgreSQL + Redis

- **PostgreSQL** — реляционная БД для хранения пользователей, партий, рейтингов. Надёжная, бесплатная, поддержка JSON для гибких структур
- **Redis** — хранение состояния активных партий, сессий, очередей матчмейкинга. In-memory скорость критична для real-time

### WebSocket: Socket.IO (через NestJS Gateway)

- Встроенная интеграция с NestJS
- Автоматический fallback на long-polling
- Rooms/namespaces для изоляции партий
- Reconnection из коробки

### ORM: Prisma

- Типобезопасные запросы, автогенерация типов из схемы
- Миграции
- Хорошо интегрируется с NestJS

## Альтернативы, которые рассматривались

| Компонент | Альтернатива | Причина отказа |
|-----------|-------------|----------------|
| Бэкенд | Go, Rust | Выше порог входа, один разработчик — важна скорость разработки |
| Бэкенд фреймворк | Express, Fastify | Меньше структуры из коробки, NestJS лучше масштабируется архитектурно |
| Фронтенд | Vue, Svelte | React имеет больше готовых шахматных компонентов |
| БД | MongoDB | Шахматные данные хорошо ложатся в реляционную модель (пользователи, партии, ходы, рейтинги) |
| WebSocket | ws, µWebSockets | Меньше абстракций, больше ручной работы |

## Последствия

- Единый язык (TypeScript) на всём стеке — проще для одного разработчика
- NestJS задаёт архитектурные паттерны, снижая риск хаоса в коде
- Redis добавляет зависимость, но необходим для real-time производительности
- Prisma может быть узким местом при сложных запросах — при необходимости можно писать raw SQL
