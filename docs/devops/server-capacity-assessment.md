## 3. Оценка ресурсов под нагрузкой

### RAM

NestJS под нагрузкой (WebSocket + active games) потребляет 200–400 MB.
PostgreSQL с активными запросами — 128–256 MB.
Итого Kingside под нагрузкой: ~350–700 MB.

**После удаления RabbitMQ доступно ~332 MB (было 194 MB).** Дефицит возникнет при >20–30 одновременных игр.

Сервер использовал 438 MB swap — после освобождения 138 MB ситуация улучшится, но swap по-прежнему будет использоваться при нагрузке.

### CPU

1 vCPU разделён между:
- nginx/php-fpm (другое приложение)
- NestJS (async I/O — терпимо)
- chess.js (CPU-bound валидация ходов)
- Stockfish (настроено `STOCKFISH_MAX_INSTANCES=4`)

4 экземпляра Stockfish на 1 vCPU — избыточно. Рекомендуется снизить до 1.

### Диск

**КРИТИЧНО: 90% занято (3 GB свободно).**

PostgreSQL, Docker-образы, логи — всё это будет расти.
При исчерпании диска база данных упадёт с ошибкой записи.

### Сеть

Ограничений по пропускной способности не выявлено. WebSocket-трафик шахматных партий минимален (~1–5 KB/сек на игру).

## 5. Обязательные действия перед деплоем

### 5.1 Освободить диск (критично)

```bash
# Удалить неиспользуемые Docker-объекты
docker system prune -f

# Проверить размер логов
journalctl --disk-usage
journalctl --vacuum-size=200M

# Найти крупные файлы
du -sh /var/log/* | sort -hr | head -20
```

**Цель**: не менее 5–7 GB свободного места.

### 5.2 Ограничить Stockfish

В `docker-compose.yml` или `.env` установить:

```
STOCKFISH_MAX_INSTANCES=1
```

### 5.3 Ограничить память контейнеров

```yaml
# docker-compose.yml
services:
  api:
    mem_limit: 400m
  postgres:
    mem_limit: 256m
  redis:
    mem_limit: 64m
```

Это предотвратит вытеснение соседних процессов.

## 7. План деплоя (при выполнении п.5)

1. Очистить диск до <80% заполненности
2. Обновить `.env` (`STOCKFISH_MAX_INSTANCES=1`)
3. Добавить `mem_limit` в `docker-compose.yml`
4. Запустить `docker compose up -d`
5. Проверить `docker stats` и `df -h` после запуска
